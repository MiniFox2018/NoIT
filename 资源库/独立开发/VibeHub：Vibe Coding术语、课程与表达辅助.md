# VibeHub：Vibe Coding术语、课程与表达辅助

## 定位

VibeHub 不是普通的“编程术语字典”，也不只是一个 Vibe Coding 教程站。它把**术语查询、场景示例、练习、课程、AI 生成界面反模式和 Agent Skill**放在同一体系里，核心用途是：

> **把“我知道自己想要什么，但不知道专业上怎么说”转成更准确、可执行、可验收的开发表达。**

它最适合两类场景：

- 用户能描述现象或目标，但不知道对应术语；
- Agent 已经开始开发，用户需要继续追加修改，却不希望因为表达模糊造成误解。

VibeHub 的价值不在于要求用户先学完一套前端 / 后端课程，而在于**需要什么概念时，就在当前任务里补足最关键的语言和边界**。

## 当前内容结构

### 1. 术语图鉴

2026-10-03 核验时，站点显示 **360 个可视化术语指南**，分布在：

- 前端；
- 后端；
- 产品；
- 测试；
- 技术栈；
- AI；
- Git；
- 设计风格。

术语条目的实用点不只是“定义”，而是会把概念放回真实开发场景，例如：

~~~text
口语描述
→ 对应术语
→ 这个术语实际解决什么
→ 可以怎样对 Agent 说
→ 什么时候适用 / 不适用
~~~

这比单纯背单词更适合 AI 编程，因为很多返工并不是不会写代码，而是**需求、组件、状态、交互和验收语言没有说清楚**。

### 2. 术语练习

当前 Practice 区显示 **334 道练习**。练习不是考拼写，而是给一个界面或产品场景，让用户判断哪种控件、结构或交互更合适。

它适合用于：

- 检查自己是否真的理解某个术语；
- 区分看起来相近的组件和交互；
- 训练“场景 → 设计 / 开发概念”的映射；
- 避免只会记名词，却不会在真实任务里选择。

### 3. 完整课程

当前《从零做一个产品官网》课程为 **9 章**，按一个完整官网任务串联：

1. 页面结构与区块分工；
2. 视觉风格与设计变量；
3. 首屏文案与 CTA；
4. 功能展示与排版布局；
5. 真实证据、定价与 FAQ；
6. 间距、贴边、溢出与层叠遮挡；
7. 按钮交互与候补表单；
8. 手机适配与抽屉导航；
9. 上线走查与 AI 协作迭代。

这套课程真正值得保留的不是某一个官网模板，而是一条稳定工作链：

~~~text
目标与结构
→ 视觉规则
→ 内容与证据
→ 交互与表单
→ 移动端适配
→ 验收
→ 再交给 Agent 迭代
~~~

因此它更接近“如何把产品网页需求表达完整”的实战教学，而不是单纯 HTML / CSS 入门课。

### 4. Avoid AI Slop

VibeHub 把常见 AI 生成内容问题分成三组、当前共 **18 个模式**：

- **英文文案套话 4 项**：抽象增强词、模板化分析动词、装饰性抽象比喻、万能开场；
- **UI 默认套路 8 项**：居中 Hero 默认式、三卡片默认式、紫色光晕、容器套容器、到处分隔线、左边框 Callout、大而重的标题、Emoji 代替图标；
- **UX 捷径 6 项**：到处动效、伪响应式、到处加解释文案、命名漂移、无效控件、图标按钮迷宫。

最重要的边界是：

> **单独一个视觉元素、词语或交互问题不能证明内容由 AI 生成；应该判断是否在缺少任务理由的情况下反复出现相同默认模式。**

这部分已经进一步吸收到 [[用户体验设计：认知规律、交互原则与信任]]，因此本资源页不重复展开完整审查方法。

### 5. VibeHub Skill

VibeHub 同时提供真实可安装的 `vibehub` Skill，官方仓库为：

https://github.com/oil-oil/vibe-hub-skill

实际 Skill 位于：

https://github.com/oil-oil/vibe-hub-skill/blob/main/skills/vibehub/SKILL.md

它有两个核心职责：

1. **Rewrite**：把模糊、口语化描述改成可直接发给 Agent 的准确需求；
2. **Proactive hints**：用户没有主动问“这叫什么”时，也在当前任务中提示最相关的 1–3 个术语。

其边界很明确：

- 保留用户原意；
- 不擅自增加框架、组件库、参数或实现方案；
- 用户已经表达准确时，不强行教学；
- 没有真正有帮助的术语时，不硬塞链接；
- 术语只用于降低沟通歧义，不用于展示专业感。

技术上，Skill 会先根据上下文推断少量候选术语，再通过随包脚本向 VibeHub 批量验证名称和页面链接。查询只发送脱敏后的短术语，不应发送源代码、密钥、客户信息、内部网址、邮箱、本地路径或完整项目材料。

当前 README 标明：

- 需要 Node.js 20+；
- 需要联网；
- 不需要账号或 API Key；
- 仓库使用 MIT License；
- VibeHub 网站不可访问或没有可靠匹配时，不应伪造术语和链接。

Skill 收藏状态见 [[Skill收藏与安装清单]]。收藏不代表已经安装或运行验证。

## 最适合什么时候打开 VibeHub

### 适合

- “这个东西专业上叫什么？”
- “我能描述效果，但 Agent 总理解错。”
- “Agent 回复里有几个术语我看不懂。”
- “我想把一句口语需求改成更准确的开发要求。”
- “这个控件 / 布局 / 状态到底应该用哪一种？”
- “这个页面看起来像 AI 默认生成的，但我说不出具体问题。”
- “我想系统练习 Vibe Coding 里高频产品与开发概念。”

### 不需要

- 用户已经准确表达了任务，继续补术语只会增加噪声；
- 需要的是框架 API、版本、报错或源码级细节，此时应直接查官方文档和代码；
- 需要完整系统学习计算机基础，VibeHub 不能替代正式教材；
- 需要判断某个具体产品的技术实现时，术语页不能替代真实仓库、运行环境和测试。

## NoIT 的长期使用方式

VibeHub 不按“把 360 个词条复制进仓库”的方式吸收。

原因是大量基础术语已经属于通用技术知识，机械复制会产生新的百科式冗余，而且站点仍在持续增加和修改词条。

NoIT 对它采用四层处理：

1. **资源层**：本页保存 VibeHub 的定位、结构、适用场景和边界；
2. **Skill 层**：`vibehub` 进入 [[Skill收藏与安装清单]]；
3. **UX 知识层**：AI Slop 的 18 个反模式融合进 [[用户体验设计：认知规律、交互原则与信任]]；
4. **AI 工作方法层**：把“口语意图 → 准确术语 → 可观察行为 → 可验收需求”的方法融合进 [[复杂任务提示词与AI写作：任务设计、材料、工具、验收与返工]]。

这样后续真正使用时：

- 查具体词：回 VibeHub；
- 做产品 / UI 评审：看 NoIT 的 UX 主知识；
- 给 Agent 写需求：看 NoIT 的复杂任务与需求表达方法；
- 想自动获得术语辅助：再考虑安装 `vibehub` Skill。
