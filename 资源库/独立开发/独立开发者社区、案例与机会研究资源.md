# 独立开发者社区、案例与机会研究资源

这份资源页不保存“值得逛的网站”，而是说明这些资源分别应该在独立开发流程的什么阶段使用。

## 快速选择

| 资源 | 最适合解决的问题 | 主要价值 |
| --- | --- | --- |
| Indie Hackers | 别的独立开发者怎么做 | 社区、产品、案例、讨论 |
| Failory | 为什么创业项目失败 | 失败案例、访谈、资料库 |
| Closed Companies | 快速查某家失败公司发生了什么 | 关闭公司档案、融资与停运原因 |
| Loot Drop | 从大量失败案例中找共性风险与可重做机会 | 失败数据库、模式分析、Deep Dive、Rebuild Plans |
| IT桔子死亡公司库 | 研究中国及相关创投语境下的死亡公司 | 公司、融资、赛道、关闭时间与原因等结构化数据 |
| RantBase | 用户在现有 App 里抱怨什么 | 差评聚类、问题与机会发现 |
| 独立开发前线 | 中文独立开发生态里有哪些产品和人 | 产品展示、创始人、文章与动态 |

## Indie Hackers

https://www.indiehackers.com/

### 它是什么

面向独立创业者、Bootstrap 创业者和小型互联网业务的社区与案例平台。

当前可用于：

- Starting Up 讨论；
- 产品与项目发现；
- 创业案例；
- Ideas 数据库；
- Build Board；
- 独立开发经验讨论。

### 什么时候值得打开

- 想验证一个问题是否有人讨论；
- 找类似产品和商业模式；
- 观察独立开发者如何获客、定价和增长；
- 找首批用户或同行反馈；
- 研究小团队真实经营过程。

### 使用方法

不要只阅读“成功营收数字”。

更有价值的是记录：

- 产品解决什么问题；
- 创始人从哪里发现问题；
- 第一批客户怎么来；
- 多久开始收费；
- 失败过哪些渠道；
- 留存来自什么；
- 哪些工作被产品化或自动化。

### 限制

社区案例有幸存者偏差。

高收入案例不能当作平均结果。

## Failory

https://www.failory.com/

### 它是什么

围绕创业失败、创始人访谈和创业资料建立的内容库。

包括失败公司案例、Startup Cemetery、访谈、文章、Pitch Deck 等内容。

### 什么时候值得打开

- 做项目反向风险检查；
- 研究某类创业为什么失败；
- 找与自己商业模式相似的失败案例；
- 做竞争和历史案例研究。

### 推荐分析模板

~~~text
公司 / 项目
→ 当时解决什么问题
→ 客户是谁
→ 商业模式
→ 获客方式
→ 核心假设
→ 出现什么证据
→ 最终失败原因
→ 哪些条件与我的项目相同 / 不同
~~~

### 限制

失败通常是多因素结果。

不要把文章标题中的单一原因当成严格因果结论。

## Closed Companies

https://www.closedcompanies.site/

### 它是什么

公开的创业公司关闭档案库，按公司记录关闭年份、行业、国家、融资规模、主要关闭原因及相关来源入口。

它比长篇案例站更适合做**第一轮快速检索**：先确认某家公司是否关闭、何时关闭、公开材料通常把主要原因归为什么，再决定是否继续深挖原始报道。

### 什么时候值得打开

- 查某个已经停运或破产的创业公司；
- 快速找同一行业的失败案例；
- 做竞品历史和“前人为什么没做成”的初筛；
- 建立产品或赛道的失败案例候选清单。

### 正确用法

把它当作**案例索引**而不是最终事实来源。

建议流程：

1. 用行业、年份、国家等信息找到相近案例；
2. 记录融资规模、关闭节点和站点归纳的主要原因；
3. 打开其关联来源，确认公司声明、破产文件、媒体报道或收购信息；
4. 再判断这个失败原因与当前项目是否具有可比性。

### 限制

- “关闭原因”通常是压缩后的摘要，不能代表完整因果链；
- 融资金额和公司状态可能来自公开报道，仍需回查原始来源；
- 被收购后下线、主动关停某产品线、公司破产等情形不能简单视为同一种失败。

核验：2026-10-04。

## Loot Drop

https://www.loot-drop.io/

### 它是什么

围绕失败创业公司建立的“Startup Graveyard”。除案例数据库外，还提供失败模式分析、Deep Dives、Dashboard、Learning Framework、Rebuild Plans、Ideas 等功能。

与 Closed Companies 相比，它不只是回答“谁死了、为什么”，而是试图继续回答：

- 哪些失败模式会反复出现；
- 某个项目今天是否存在重新实现的可能；
- 如果重新做，应避免哪些旧路径；
- 从大量失败样本中可以提炼哪些风险信号。

因此它更接近**创业反例研究与机会发现平台**，而不是普通工具。

### 什么时候值得打开

- 给新项目做 pre-mortem（事前验尸）；
- 搜索同类商业模式过去如何失败；
- 对比多个失败案例，找重复出现的产品、竞争、现金流、监管或运营问题；
- 从已经被验证过需求、但执行失败的方向中寻找可重新设计的机会。

### 推荐使用方式

不要直接把“失败项目存在过”理解为“这个市场已被验证”。

更可靠的流程是：

1. 找 5—10 个真正相近案例；
2. 区分需求失败、产品失败、渠道失败、单位经济失败、竞争失败、融资失败与监管失败；
3. 对照今天的技术、成本、分发渠道和政策条件是否已经改变；
4. 明确“当年错误”与“今天仍然存在的结构性问题”；
5. 再回到真实用户做需求验证。

### 限制

- 网站明确说明部分内容使用 AI 辅助总结与分析，不能把归因直接当成经过严格验证的事实；
- 聚合数据适合发现模式，不适合替代公司原始声明、财务材料、监管文件与可靠媒体报道；
- “Rebuild”或“Ideas”属于启发和假设，不代表商业可行性已经被验证；
- 当前站点较新，长期稳定性和数据连续性仍需后续观察。

核验：2026-10-04。

## IT桔子死亡公司库

https://www.itjuzi.com/deathCompany

### 它是什么

IT桔子创投数据体系中的死亡公司专题库。其价值不只在“公司已经关闭”这一标签，而在于能够把死亡公司与公司画像、赛道、成立时间、融资阶段、融资事件、关闭时间和关闭原因等创投维度关联起来。

相较于前两个英文站点，它更适合补充**中国创业、互联网和创投市场语境**，尤其适合按赛道、融资阶段和时间周期观察企业消亡。

### 什么时候值得打开

- 研究中国某一赛道过去倒下过哪些公司；
- 对比不同融资阶段的失败样本；
- 观察某一轮创业周期中的公司进入与退出；
- 给中国市场项目做竞品历史与创投背景研究；
- 与 IT桔子的公司库、投融资事件等数据交叉核对。

### 使用注意

IT桔子对“死亡公司”的判断包括公开关闭、破产清算，以及注销、产品长期不更新等明显无法持续经营的情况。因此研究时应进一步区分：

- 法律意义上的破产 / 清算；
- 公司注销或停止经营；
- 产品或业务线关闭；
- 被收购后品牌消失；
- 长期无更新、被判断为停止运营。

这些状态的商业含义并不完全相同。

### 限制

- IT桔子属于商业数据平台，公开可见范围、筛选、下载和完整数据权限可能随会员体系变化；
- 历史条目和“死亡”状态仍需结合公司官方信息、工商状态和可靠报道复核；
- 如果以后要收录 IT桔子**整个主站**，它更适合同时进入“信息、数据与行业研究资源”；本次用户提供的是“死亡公司库”子页面，因此这里只按创业失败研究用途收录，避免重复归档。

核验：2026-10-04。

## RantBase

https://rantbase.app/reviews

### 它是什么

把真实 App Store 评论做结构化分析的 AI 工具。

当前页面提供大量应用评论分析，可用于搜索：

- 用户问题；
- 缺失功能；
- 反复抱怨；
- 潜在产品机会。

### 什么时候值得打开

最适合“我想找值得解决的问题，但还没有明确产品方向”的阶段。

### 正确用法

1. 找目标领域中的成熟 App；
2. 看 1—3 星评论；
3. 对重复问题聚类；
4. 区分 bug、单纯情绪与结构性需求；
5. 找用户现在如何绕过问题；
6. 再通过访谈、着陆页或 MVP 验证。

### 限制

- App Store 用户不代表全部市场；
- 差评可能受版本、设备和短期故障影响；
- 高频抱怨不等于高付费意愿；
- AI 提取的“机会”仍需要人工判断。

## 独立开发前线

https://indiefront.cn/

### 它是什么

中文独立开发者社区和产品展示平台。

当前网站聚合：

- 独立产品；
- 创始人；
- 文章；
- 产品更新；
- 活动。

### 什么时候值得打开

- 了解中文独立开发生态；
- 找国内同类产品；
- 发现创始人经验；
- 找发布、合作和交流对象；
- 观察中文市场实际产品形态。

### 限制

它更适合生态观察与发现，不应替代：

- 市场规模研究；
- 用户访谈；
- 官方政策；
- 产品真实经营数据。

## 失败案例资源怎么分工

如果只是要快速找到“类似项目以前怎么死的”，优先顺序可以是：

~~~text
Closed Companies
→ 快速找到案例与基本死因

Loot Drop
→ 看更多相似案例、失败模式、Deep Dive 与重建假设

IT桔子死亡公司库
→ 补中国市场、融资轮次、赛道和创投上下文

Failory
→ 阅读更完整的创业故事、访谈和失败复盘

原始来源 / 公司声明 / 监管与工商材料
→ 最终事实核验
~~~

这四类资源不是越多越好。真正有价值的是对**与你当前项目高度相似的失败样本**做深入对比，而不是浏览大量“创业墓地”。

## 推荐工作流

~~~text
RantBase 找用户痛点
→ Indie Hackers / 独立开发前线找相似产品与真实经营经验
→ Closed Companies / Loot Drop / IT桔子 / Failory 查历史失败模式
→ 提炼“我的项目最可能怎么死”
→ 形成风险假设与最小验证方案
→ 回到真实目标用户、成本结构和渠道数据验证
~~~

这些资源的共同用途不是证明一个想法值得做，而是更早发现**不该怎么做**、哪些前提必须先验证。
