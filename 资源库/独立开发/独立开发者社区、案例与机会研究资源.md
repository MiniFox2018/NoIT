## Indie Hackers

https://www.indiehackers.com/

### 它是什么

面向独立创业者、Bootstrap 创业者和小型互联网业务的社区与案例平台。

当前可用于：

- Starting Up 讨论；
- 产品与项目发现；
- 创业案例；
- Ideas 数据库；
- Build Board；
- 独立开发经验讨论。

### 什么时候值得打开

- 想验证一个问题是否有人讨论；
- 找类似产品和商业模式；
- 观察独立开发者如何获客、定价和增长；
- 找首批用户或同行反馈；
- 研究小团队真实经营过程。

### 使用方法

不要只阅读“成功营收数字”。

更有价值的是记录：

- 产品解决什么问题；
- 创始人从哪里发现问题；
- 第一批客户怎么来；
- 多久开始收费；
- 失败过哪些渠道；
- 留存来自什么；
- 哪些工作被产品化或自动化。

### 限制

社区案例有幸存者偏差。

高收入案例不能当作平均结果。

## Failory

https://www.failory.com/

### 它是什么

围绕创业失败、创始人访谈和创业资料建立的内容库。

包括失败公司案例、Startup Cemetery、访谈、文章、Pitch Deck 等内容。

### 什么时候值得打开

- 做项目反向风险检查；
- 研究某类创业为什么失败；
- 找与自己商业模式相似的失败案例；
- 做竞争和历史案例研究。

### 推荐分析模板

~~~text
公司 / 项目
→ 当时解决什么问题
→ 客户是谁
→ 商业模式
→ 获客方式
→ 核心假设
→ 出现什么证据
→ 最终失败原因
→ 哪些条件与我的项目相同 / 不同
~~~

### 限制

失败通常是多因素结果。

不要把文章标题中的单一原因当成严格因果结论。

## RantBase

https://rantbase.app/reviews

### 它是什么

把真实 App Store 评论做结构化分析的 AI 工具。

当前页面提供大量应用评论分析，可用于搜索：

- 用户问题；
- 缺失功能；
- 反复抱怨；
- 潜在产品机会。

### 什么时候值得打开

最适合“我想找值得解决的问题，但还没有明确产品方向”的阶段。

### 正确用法

1. 找目标领域中的成熟 App；
2. 看 1—3 星评论；
3. 对重复问题聚类；
4. 区分 bug、单纯情绪与结构性需求；
5. 找用户现在如何绕过问题；
6. 再通过访谈、着陆页或 MVP 验证。

### 限制

- App Store 用户不代表全部市场；
- 差评可能受版本、设备和短期故障影响；
- 高频抱怨不等于高付费意愿；
- AI 提取的“机会”仍需要人工判断。

## 独立开发前线

https://indiefront.cn/

### 它是什么

中文独立开发者社区和产品展示平台。

当前网站聚合：

- 独立产品；
- 创始人；
- 文章；
- 产品更新；
- 活动。

### 什么时候值得打开

- 了解中文独立开发生态；
- 找国内同类产品；
- 发现创始人经验；
- 找发布、合作和交流对象；
- 观察中文市场实际产品形态。

### 限制

它更适合生态观察与发现，不应替代：

- 市场规模研究；
- 用户访谈；
- 官方政策；
- 产品真实经营数据。

## 推荐工作流

~~~text
RantBase 找痛点
→ Indie Hackers / 独立开发前线找相似产品与人
→ Failory 查失败模式
→ 形成假设
→ 回到真实目标用户验证
~~~

四个平台角色不同，互补使用比持续刷单一社区更有价值。
