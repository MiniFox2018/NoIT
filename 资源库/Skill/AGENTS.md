# Skill 目录操作规则

> 本文件适用于 `资源库/Skill/` 及其子目录。处理本目录前，先读取仓库根目录 `PROJECT_RULES.md`，再读取本文件和相关现有内容。用户当前明确要求始终优先。

## 1. Skill 资料的核验与归类

- 不凭仓库名、宣传文案或“Skill”字样直接判断。新提交链接应尽量检查 README、实际 `SKILL.md` 及必要支持文件；网页则核对正文和项目来源。
- **实际 Skill** 或包含实际技能的合集、技能包：并入 `Skill收藏与安装清单.md`。合集放在“收藏的技能合集”，不作为一个单独 Skill 计数。
- **Skill 聚合网站、导航、目录、搜索平台**：并入 `Skill网站与导航.md`。网站中的具体技能不默认全部展开收录。
- **Skill 教程、使用方法、实践经验、解读文章**：先并入 `Skill教程与实践笔记.md`；如果其中形成可脱离具体 Skill 独立复用的方法论，再按根规则吸收到知识库对应主题。
- 其他与 Skill 明确相关的资料，先查找现有合适文档；只有确有必要时才新增中文命名文档，避免“一条链接一篇笔记”。
- 与 Skill 完全无关的内容不进入本目录；关联不明确或暂时无法访问时标明待核实，不把“无法核实”写成“不是 Skill”。

## 2. Skill 与合集、同名项、重复项

- 仅同名不足以认定为同一 Skill；结合来源、实际 `SKILL.md`、用途和支持文件判断。
- 单个 Skill 与包含它的合集可以同时存在：单项回答“这个技能能做什么”，合集回答“这组技能覆盖什么工作流”；避免重复统计。
- 已有条目收到新的官方或仓库链接时，优先补充来源而不是新增重复项。
- 某个 Skill 同时包含成熟方法论、工作流或架构知识时，采用 NoIT 的“知识 + 资源双轨处理”，不把方法论只埋在收藏清单里。

## 3. 安装状态

- “收藏”“已安装”“当前会话可用”“依赖存在”“实际运行验证通过”是不同状态，不得混写。
- 安装状态需要证据。能访问当前环境时再重新核对；无法重新核对时，保留最近一次带日期的历史快照，不把历史状态写成实时结论。
- 合集只安装部分时可标为“已安装（部分）”；使用适配版本时注明适配环境。
- 整理、审核或收藏 Skill **不授权**安装、升级、运行、启用插件、购买服务或对外发布；只有用户明确要求相应动作时才执行。

## 4. 链接与可移植性

- NoIT 是跨设备长期仓库，优先保存官方站点、GitHub 仓库、公开 `SKILL.md` 等可长期访问来源。
- 本机 `file://` 路径、用户目录绝对路径等不写入仓库长期资源清单；仅有本机说明文件时，保留准确 Skill 名称、用途和带日期的安装状态，待未来发现公开来源再补。
- 链接失效时先寻找同项目的当前官方入口；不能确认时保留待核实说明，不猜测替代地址。

## 5. 文档布局

- 使用中文说明，保留准确 Skill 名称。
- 用途写清“能做什么、主要特点、适用任务和关键边界”，不得把宣传效果或未测试能力写成已验证结果。
- `Skill收藏与安装清单.md` 保持三列：`用途`、`Skill · 点击查看说明`、`安装状态`。
- 各用途分类内保持连续 Markdown 表格；不为每个 Skill 单独建文档。
- 保留用户已经做出的删减、编辑和分类；除非新证据或用户新指令要求调整，不凭旧聊天把已删除内容补回。

## 6. 完成检查

每次处理新 Skill 相关资料后至少检查：

1. 新链接是否全部得到明确处理：收录、合并、待核实或剔除；
2. 是否误把导航、教程或工具项目当成单个 Skill；
3. 是否出现同名不同来源被错误合并；
4. 安装状态是否有证据和日期；
5. 是否引入了本机绝对路径；
6. 如果资料含长期方法论，是否需要同步更新知识库；
7. README 或相关索引是否需要补入口。
