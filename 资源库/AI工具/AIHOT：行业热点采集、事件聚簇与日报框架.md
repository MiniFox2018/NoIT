# AIHOT：行业热点采集、事件聚簇与日报框架

**官方代码**：https://github.com/KKKKhazix/AIHOT  
**线上产品**：https://aihot.news/  
**项目类型**：可自部署、可改造的垂直行业新闻精选与日报系统。代码 MIT 许可；AIHOT 名称、标识及部分第三方素材不在 MIT 授权范围内。

## 解决什么问题

面向法律、HR、金融或任何有自己信源的行业，构建「采集 → 两轮独立评分 → 同事件聚簇 → 热度排序 → 编辑综述 → 生成日报 → 网站/API/RSS/MCP 分发」的流水线。不同领域需要自己提供高质量信源、偏好规则、拒收标准和行业知识，开源框架不会自动替代这些判断。

这与 NoIT 的信息流和个人情报系统有直接参考价值，但**资源登记不等于将其上线、替换现有系统或断言已经可用**。

## 核心流程及需要保留的设计

1. **入口采集**：按信源类型配置来源、抓取频率、文章时间和增量导入规则，避免把抓取成功误认作内容完整。
2. **初筛与精选**：大模型先剔除不相关项，候选再独立评分；提示词、门槛和筛选样本应可配置及复核。评分不能只看模型自信程度。
3. **事件聚簇**：多篇报道同一事实时合并成一个事件，保存各自原标题和原始 URL；单篇独立信息也可以成为事件。要测试误合并、误拆分和事件时间线。
4. **热度与综述**：区分「多少独立源报道」与「信息本身是否重要」，不要把重复转载算成独立证据；综述应有来源追溯，不凭模型补背景。
5. **周期输出**：将精选事件组织为日报等内容，保留筛选原因、时效、发布状态及错误重试记录。
6. **外部接口**：框架提供网站、后台、API、RSS 和 MCP 等对外入口；迁移到个人项目时应按实际需求选择，避免同时维护多个重复分发层。

## 与个人信息流系统的可复用设计

- 按「信息源层 → 事件层 → 报告层」建模，不以文章列表直接冒充报告。
- 评分拆为可靠性、原创性、相关性、事件价值和综合排序；保留人工调整权。
- 事件唯一标识、多个独立来源、发布时间与采集时间分开；每日、每周、每月、每年沿自然周期归档。
- 设置事件关系评测样本，计算误归并/漏归并；内容精选维护正反例样本。上线前跑历史回放，不仅看一天的演示。
- 将密钥、抓取权限、原文版权、站点负载、容错重试、安全隔离列入上线核查清单。
- **不把作者所述百万月活、近十万 Skill 用户当作已独立审计的指标**。它们是作者提供的项目背景数据。
