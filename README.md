# NoIT

由用户主动投喂资料、由 AI 持续完成核验、去重、融合和知识沉淀的个人知识、方法与资源库。

NoIT 不负责替代用户在不同平台上的收藏习惯。用户将值得长期保留的链接、网页、PDF、文档等资料提交后，再由 AI 与仓库现有内容进行比对、核验和融合。

NoIT 与 Study 当前暂时独立维护，未来计划合并为统一仓库。合并前，两边继续按各自现有结构吸收资料；遇到跨领域内容时，以当前任务所属仓库为处理基准，不做重复入库，待正式合并时再统一去重和重构导航。

## 使用原则

- 收藏只是来源，仓库保存的是经过吸收后的长期价值。
- 同主题多来源优先融合，不默认“一篇来源对应一篇笔记”。
- 同一批次提交不代表同一主题，资料逐篇独立判断。
- 正式知识应尽量做到脱离原始网页也能独立学习和查阅。
- 文档默认使用 Markdown，并兼顾 GitHub 与 Obsidian。
- 长期处理规则统一见 [PROJECT_RULES.md](./PROJECT_RULES.md)。
- 44 篇知识正文的审计范围、材料缺口和复核优先级见 [2026-10-08 知识内容审计记录](./.github/audits/2026-10-08-knowledge-44.md)；该记录不代表所有原始资料已再次逐章验收。
- AI 工具入口见 [AGENTS.md](./AGENTS.md)。
- 新增、删除或重命名正式知识 / 资源文档时，同步检查本 README 索引。
- 仓库基础一致性由 `scripts/audit_repository.py` 配合 GitHub Actions 自动检查，包括正式文档元数据、标题一致性、日期与状态、唯一 H1、README 索引、内部链接、本机绝对路径，并对来源记录、标题层级、知识孤岛、`verified` 一致性和长期未核验资源给出治理提醒。
- 外部 URL 由 `scripts/audit_external_links.py` 通过独立的周期性 GitHub Actions 做非阻塞巡检；`404/410` 只代表疑似失效，登录墙、限流、反爬、网络或 TLS 异常同样只作为待复查信号；仅有独立可靠证据才能认定永久失效，不自动删除资源。

### 分类边界

- **AI视频 / 影像创作**：前者偏生成模型、控制与 AI 视频工作流；后者偏镜头语言、叙事、拍摄和整体创作方法。
- **AI工具 / 工具库**：前者是值得独立维护的重要 AI 工具或平台；后者是批量收藏的轻量资源索引。
- **学习资源 / Study**：前者保存教材、课程和专题站等学习入口；系统学习正文在正式合并前继续按当前任务所属仓库处理。
- **正式知识 / 随手摘录**：前者保存经过系统吸收的长期知识；后者保留暂不值得扩写的碎片观点和实践观察。
