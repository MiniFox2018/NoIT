# AI视频导演式Prompt编译：镜头表、参考权、连续性与返工

## 这套方法解决什么问题

AI 视频提示词写作如果只停留在“把画面描述得更详细”，很容易出现一种错觉：

> Prompt 已经很长，但模型仍然不知道镜头真正要完成什么。

更稳定的方法不是继续堆形容词，而是把生成前的思考拆成几个明确阶段：

1. 先确定镜头的叙事或功能目标；
2. 再确定空间、人物、参考素材和连续性；
3. 用结构化镜头计划检查遗漏；
4. 最后才把这些信息“编译”为自然语言 Prompt；
5. 生成后不是直接重抽，而是先判断哪里失败、什么应该保留、下一次只改什么。

Emily2040 的 Seedance 2.0 Skill OS 将这套思路实现成一个面向 AI Agent 的多 Skill 系统。它真正值得长期保留的不是某个固定 Prompt，而是：

> **把视频生成从“写 Prompt”升级成“导演决策 → 镜头合同 → Prompt 编译 → Take Review → 状态更新”的循环。**

---

## 一、先决定“这一镜为什么存在”

“电影感”“高级”“史诗”“情绪化”都不是足够具体的导演决定。

镜头真正需要的是一句可以指导所有制作选择的意图，例如：

- 让观众在这一镜第一次意识到角色已经失去控制；
- 让产品的某个功能在一次真实动作中被看懂；
- 让人物的犹豫通过一个动作而不是对白表达；
- 让这一镜完成从安全到危险的转折。

然后再让：

- 机位；
- 镜头运动；
- 光线；
- 表演；
- Blocking；
- 声音；
- 剪辑节奏；

共同服务这个目的。

### 情绪必须变成可见行为

模型不能直接“拍到悲伤”。

更可执行的是：

- 她把信折好后压平，却始终不抬头；
- 他擦同一个位置两次，然后停住；
- 她口头答应，却向后退了一步。

因此：

> **抽象情绪负责内部判断，可见动作负责进入生成 Prompt。**

---

## 二、多镜头或多人场景，先做 Shot Table，再写 prose

这是该仓库最值得吸收的方法之一。

对多镜头或多人物场景，不应从一段自然语言 Prompt 开始，而应先建立一张“纸面镜头表”。

### 先写一个可画出来的空间说明

至少明确：

- 固定地标：门、桌子、窗、柜台、道路等；
- 人物起始位置；
- 人物面向；
- 光源位置和颜色；
- 主要空间轴线。

如果陌生人无法根据文字画出大致平面关系，说明空间还没定义清楚。

### 每个 Shot 至少写清楚

| 字段 | 需要明确什么 |
| --- | --- |
| Camera | 摄像机在空间哪一侧，景别是什么 |
| In frame | 谁在画面里，站/坐哪里，朝向哪里 |
| Eye-line | 谁看谁、看向哪里 |
| Action | 这一镜唯一核心动作是什么 |
| Others | 其他人在做什么，而不是全部静止 |
| Light | 光源与颜色是否延续 |
| Last frame | 镜头结束时画面实际能看到什么 |

### 空白字段不是“小问题”

AI 往往会替你补默认答案：

- 没写摄像机在哪 → 自动选常见构图；
- 没写人物朝向 → 可能直视镜头；
- 没写从门口走到桌边 → 人物可能像瞬移；
- 没写其他人在做什么 → 群众可能冻结或随机动作；
- 没写光线 → 跨镜头色温漂移。

因此，Shot Table 的本质是：

> **在花生成成本之前，把模型会被迫猜测的空白先找出来。**

---

## 三、位置不够，必须同时写“位置 + 朝向 + Camera side”

连续性经常不是人物身份出错，而是空间几何出错。

例如：

- 角色在门边，却突然从另一侧出现；
- 角色明明看向门口，反应镜头却像在看镜头；
- 正反打时视线方向错乱；
- 一个人上一镜在桌边，下一镜无过渡回到门口。

因此人物空间状态至少需要三个维度：

```text
角色在哪里
+
角色朝向哪里
+
摄像机在空间哪一侧
```

反应镜头尤其要注意 eyeline。

如果人物正在看某个对象，反应镜头通常应该从该对象所在方向反拍，让视线越过镜头指向目标，而不是让人物无缘无故看向摄影机。

---

## 四、一个镜头尽量只有一个主动作

生成模型在短时间内同时执行太多动作时，很容易：

- 忽略后半段；
- 改变动作顺序；
- 省略过渡；
- 把多个动作合成奇怪动作。

因此可以采用：

> **one action per shot**

但这不代表其他人完全静止。

更合理的是：

- 一个主体承担当前主要动作；
- 其他人保持简单、持续的 idle business；
- 如果另一个角色也要完成重要动作，就给他独立镜头。

### “走过去”本身也是动作

从门口到桌边、从街对面到车边，如果空间跨度对剧情重要，就应该让移动出现在镜头里。

否则：

```text
门口
→ cut
→ 手已经在桌上
```

会产生视觉瞬移。

---

## 五、道具动作要写“机械过程”，不要只写结果动词

“倒茶”“递过去”“翻转杯子”都是结果。

对于容易失败的精细动作，更可靠的是写：

- 哪只手；
- 握哪里；
- 怎样倾斜；
- 液体流向哪里；
- 道具最后停在哪里。

例如不是：

> 她翻转杯子。

而是：

> 她转动手腕，把杯口朝下放在桌布上。

这条原则适用于：

- 拿取；
- 倾倒；
- 插入；
- 按按钮；
- 开门；
- 交接物体；
- 工具操作。

如果动作需要两次抓握、空中重新定向或复杂接触，通常更适合拆成两个镜头。

---

## 六、参考素材必须先分配“控制权”

有图片、视频、音频等多个参考时，最危险的写法是：

> “综合参考这些素材。”

因为模型不知道每个素材到底控制什么。

更清楚的做法是先建立 reference role map。

### 常见控制维度

图片适合：

- identity；
- product；
- costume；
- pose；
- environment；
- first / last frame。

视频适合：

- motion；
- camera；
- pacing；
- blocking；
- gesture rhythm。

音频适合：

- rhythm；
- tempo；
- ambience；
- delivery tone。

文本负责：

- 当前动作；
- 叙事目标；
- 约束；
- 禁止转移的属性。

### 每个维度只能有一个主要 owner

例如：

```text
Image A → 角色身份
Video B → 动作节奏
Audio C → 节拍
Text → 当前场景和动作
```

同时必须说明“不应该转移什么”。

例如：

> 视频只控制动作，不继承其中演员、服装、房间或 Logo。

这比简单说“参考这个视频”稳定得多。

这与 [[参考视频动作迁移与白模控制]] 中的分层控制完全一致。

---

## 七、视觉参考存在时，文字只写“参考素材无法携带的差量”

这是一个非常重要的 Prompt 压缩原则。

如果已经上传上一镜最终帧或角色图，就没有必要在文字中把画面里已经明确的信息完整重述一次。

可以理解成：

> **source carries state, text carries delta**

### 视频参考可以携带

- 静态外观；
- 动作阶段；
- 镜头运动；
- 环境状态；
- 音频阶段。

文字只补：

- 这个参考承担什么角色；
- 下一步动作；
- 最终要到达什么状态；
- 已知容易漂移的关键锁定项。

### 最终帧只能携带静态状态

还需要文字补：

- 尚未完成的运动方向；
- 摄像机正在怎样移动；
- 音频进行到哪；
- 下一镜动作。

### 没有视觉参考

才需要在文本中重新描述完整起始状态。

这能降低 Prompt 冗余，也减少“文字和图像互相矛盾”导致的漂移。

---

## 八、多镜头 Seedance 2.0：优先写镜头顺序，不依赖精确秒点

该仓库根据字节官方资料整理出一条需要特别注意的 2.0 版本规则：

> Seedance 2.0 更适合按 Shot 1 / Shot 2 / Shot 3 的事件顺序组织，而不是在每个镜头里依赖精确的“0–3秒、3–6秒”时间段。

精确 timestamp 在 2.0 上不应被当作可靠控制方法。

更适合写：

- Shot 1；
- Shot 2；
- Shot 3；
- “停留一个节拍”；
- “直到手完全停下”。

总时长仍由使用平台的 duration 参数负责。

### 这条知识具有版本边界

截至 2026-10-03，字节官方已经发布 Seedance 2.5。2.5 支持最长 30 秒单次生成，并进一步加强长叙事、参考和编辑。2.0 的时长、控制方式、平台字段不能直接套到 2.5。citeturn928000search0turn928000search1

所以：

> **导演方法可以跨版本复用，具体数值和语法必须按模型线重新核验。**

## 九、不要把所有 Beat 塞进一条生成

一个镜头计划需要同时考虑：

- Shot 数量；
- 对白；
- 多人物；
- 身体接触；
- 道具接触；
- 镜头运动；
- 场景切换；
- 声音同步。

仓库给出了一套“负载评分”来判断 Safe / Stretch / Ambitious。

这套具体常数是作者自己设计的启发式方法，并且仓库明确承认尚未得到完整模型实测标定，因此不应该把数字当作官方限制。

真正值得保留的是判断逻辑：

> **一条生成能承担的信息密度有限。**

当出现：

- 对白被截断；
- Shot 被省略；
- 动作被压缩；
- 多主体行为混乱；

更合理的修复往往是：

> **拆成两次生成，而不是继续把同样复杂的 Prompt 重抽。**

---

## 十、续写必须以“已经验收的真实结果”为准

长序列制作最常见的错误是：

> 计划里 Clip 1 应该停在 A，因此 Clip 2 就从 A 开始。

但实际生成的 Clip 1 可能停在 B。

如果 Clip 2 仍然从计划 A 开始，就会造成连续性断裂。

因此：

> **accepted observed state overrides planned state**

即：

- 已接受成片里的真实结束状态 > 原计划；
- rejected footage 不进入 canon；
- 下一镜必须基于上一镜已经验收的真实结果；
- 如果上一镜意外提前完成了后续剧情 Beat，后面的计划必须更新。

### 一个合理的连续性记录

至少包括：

- 人物位置与朝向；
- 姿态；
- 视线；
- 道具归属和状态；
- 环境；
- 光线；
- 摄像机运动阶段；
- 未完成动作；
- 对白和声音状态。

### Agent 能看，就不要让用户当状态传感器

如果系统真的可以检查视频或最终帧，应由 Agent 直接读取可见状态。

如果客户端不能实际查看媒体，就必须明确：

> 当前只能根据用户描述记录，不能假装自己看过。

这是一条非常重要的 AI 工作规范。

---

## 十一、长项目要区分“机器真相”和“可读 Capsule”

随着镜头越来越多，完整状态会膨胀。

该仓库采用两层：

### Machine truth

完整结构化项目状态：

- JSON；
- Clip lineage；
- Take history；
- references；
- continuity；
- observed state。

### Project State Capsule

给新会话或 Agent 快速恢复上下文的紧凑 Markdown / 文本摘要。

只保留：

- 故事目标；
- 当前场景；
- 当前真实状态；
- 已完成 Beat；
- 下一镜任务；
- continuity locks；
- 尚未解决的不确定性。

完成的旧场景被压缩，而不是每次把整个历史重新塞进 Prompt。

这与 [[AI长片规模化制作：Prompt规范、连续性与工程档案]] 中的“上下文编译”是同一方向：

> **项目状态可以很大，但当前生成上下文必须小而精确。**

---

## 十二、Prompt Compiler：内部结构化，输出仍然自然语言

内部可以使用：

- JSON；
- YAML；
- Shot Table；
- Project State；
- Clip Contract；
- Reference Map。

但最终发送给视频模型的内容不需要把内部标签全部暴露出去。

编译过程可以理解为：

```text
项目状态
+ 当前Clip合同
+ 参考素材角色
+ 当前真实起点
+ 当前动作
+ 连续性锁
+ 镜头意图
+ 禁止提前发生的Beat
        ↓
Prompt Compiler
        ↓
当前这一条自然语言生成Prompt
```

不应该把：

- hidden objective；
- power shift；
- provenance；
- internal state；
- future clip plan；

等内部管理字段原样塞给模型。

真正进入 Prompt 的应该是它们的**可见或可听表现**。

## 十三、返工不是“再抽一次”，而是一次决策

拿到失败 Take 后，先选 Verdict：

### Keep

已经达到关键验收标准，不为模糊的“再好一点”继续花成本。

### Fix in post

问题是局部的，剪辑或后期更容易解决。

### Edit

平台支持局部编辑，并且能锁住已经正确的部分。

### Re-roll

Prompt 本身没有明显问题，新的随机样本仍然能回答一个有价值的问题。

### Rewrite

已经找到具体：

- 歧义；
- 冲突；
- 缺失动作；
- 几何问题。

只修改最相关变量。

### Stop / change approach

继续生成的期望价值已经很低，或者预算耗尽。

这种分类能避免：

> 看到失败 → 改五个地方 → 重抽 → 不知道到底哪项修改有效。

---

## 十四、一次返工尽量只改一个相关变量

做诊断时，应尽量：

- 保留已经成功的部分；
- 写明失败标准；
- 写明证据；
- 提出一个最可能有用的改动；
- 其他设置保持不变。

如果必须同时改多项，要明确：

> 这是 combined repair，不能把成功归功于某一个变量。

这种思路使生成过程逐渐接近实验，而不是赌博。

---

## 十五、预算和授权也是生成系统的一部分

这个仓库有一个很成熟的原则：

> Agent 帮用户写 Prompt，不等于自动获得替用户花钱生成的授权。

因此系统应区分：

- 允许 review；
- 允许 rewrite；
- 允许 upload；
- 允许 generation；
- 允许 edit；
- 允许额外 Take；
- 金额上限。

“再试一次”不自动意味着：

- 升更贵的模型；
- 增加时长；
- 提高分辨率；
- 无限增加尝试。

这条原则尤其适合 Agent 自动化工作流。

---

## 十六、规则有优先级，风格永远不能压过连续性

该仓库给出的优先级很值得借鉴：

1. 安全、权利、授权；
2. 当前平台真实支持的能力；
3. 用户明确不可妥协的要求；
4. 参考素材合同；
5. 连续性；
6. 动作与物理因果是否可读；
7. Camera / editing；
8. 风格、色彩、氛围；
9. 系统自己的默认偏好。

它解决了一类常见错误：

- 为了一个漂亮运镜，把关键动作遮掉；
- 为了“电影感”，破坏角色身份；
- 为了风格参考，让场景连续性漂移。

一个很好的判断原则是：

> **镜头语言是为内容服务的，不是反过来。**

## 十七、哪些方法已经有较强证据，哪些仍是作者经验

这个仓库在证据边界上做得比较认真。

### 较可靠的部分

- Seedance 2.0 的四模态输入和多模态参考能力，与字节官方一致。citeturn928000search3turn928000search10
- Seedance 2.0 支持多镜头输出；

### 仓库作者自己的方法和启发式规则

包括：

- Safe / Stretch / Ambitious 的负载评分；
- 某些 Shot 复杂度常数；
- 一些镜头数量建议；
- Director's Read 的字段设计；
- Shot Table 的强制结构；
- 一些“模型容易失败”的经验性总结。

这些非常值得实践，但不能伪装成字节官方规格。

> 结构验证通过，不代表生成质量已经被完整证明；live model score 和 rendered pilot 仍有待进一步收集。

## 十八、仓库内部也存在版本文档漂移

核验于 2026-10-03：

- 根 README 标记版本为 **v6.7.0**；
- 根 `SKILL.md` metadata 也是 **6.7.0**；
- 但 `V6_SEQUENCE_PROMPT_COMPILER_MANIFEST.md` 的 “Current Patch” 仍写 **6.6.0**。

因此使用这种快速迭代项目时，不应该假设每份文档永远同步。

更稳妥的是：

1. 以 root skill / release metadata 为主要版本入口；
2. 查看最近 commit；
3. 对具体规则确认对应文件更新时间；
4. 对平台 API、价格、限制重新查官方来源。

## 十九、和NoIT已有AI视频知识的关系

### [[AI短片资产化制作工作流：角色、场景、道具与逐镜头生成]]

负责：

> 角色、场景、道具等资产如何建立和复用。

本文负责：

> 资产准备好以后，一条具体镜头怎样从导演意图编译为可执行 Prompt，并如何返工。

### [[AI长片规模化制作：Prompt规范、连续性与工程档案]]

负责：

> 数百、数千镜头如何管理项目状态、版本和工程档案。

本文补充：

> 下一 Clip 应如何基于 accepted footage 更新 canon，并将项目状态压缩成当前 Prompt 所需上下文。

### [[参考视频动作迁移与白模控制]]

负责：

> 视频参考 / Depth / 白模怎样控制动作和镜头。

本文补充：

> 多个参考素材之间如何分配控制权，避免身份、动作、场景和声音互相污染。

## 二十、一套可复用的最小导演式流程

```text
用户意图
   ↓
明确这一镜的功能 / 感受
   ↓
确定角色、空间、参考素材
   ↓
为参考素材分配控制权
   ↓
多镜头/多人时先写 Shot Table
   ↓
检查 Camera / Position / Facing / Eyeline
   ↓
拆成一个动作一个镜头
   ↓
编译成自然语言 Prompt
   ↓
生成 Take
   ↓
检查是否满足 must-pass criteria
   ↓
Keep / Post / Edit / Re-roll / Rewrite / Stop
   ↓
接受的实际结果更新 Canon
   ↓
下一镜从真实状态继续
```

核心不是写出最长的 Prompt，而是：

> **在生成之前减少模型必须猜测的空白，在生成之后把真实结果写回下一轮。**

---


## 二十一、补充：把 Prompt 写成“镜头说明”，而不是标签集合

Magnific 的《The Prompting Handbook》提供了一组更偏现场导演与摄影语言的补充规则。这些内容与前文的 Shot Table / Prompt Compiler 不冲突，而是回答：

> **当镜头合同已经确定后，怎样把它写成模型真正能执行的拍摄指令。**

一个视频 Prompt 可以至少覆盖：

| 部分 | 需要回答什么 |
| --- | --- |
| Shot | 景别与画幅，例如 9:16 中景 |
| Camera move | 当前这一镜唯一主要运镜 |
| Subject | 谁 / 什么在画面里 |
| Action | 当前这一镜唯一主动作 |
| Setting | 地点、时间、环境 |
| Lighting | 可见光源与方向 |
| Style | 画面完成态 |
| Audio | 环境声、音效、对白、是否音乐 |

更稳妥的写法不是“cinematic, epic, 4K”，而是：

~~~text
竖版 9:16 中景。
一只手从晨光厨房台面拿起咖啡壶。
镜头快速但稳定地向前推近。
自然晨光，明亮、干净。
环境声：轻微倒水声与厨房底噪。
无音乐，无字幕。
~~~

---

## 二十二、Start / End Frame 与 Reference 的职责必须分开

这两类控制经常被混为一谈。

### Start / End Frame 控制“这一镜从哪里开始、到哪里结束”

它们固定的是**时刻**：

- 第一帧；
- 可选最后一帧；
- 中间运动由模型补全。

它们适合控制：

- 开场构图；
- 最终落点；
- 单镜头运动区间。

### Reference 控制“谁 / 什么 / 怎样运动”

参考素材固定的是**身份或规律**：

- 图片参考 → 角色、产品、服装、风格；
- 视频参考 → 动作、运镜、节奏；
- 音频参考 → 声音、节拍、表演语气。

因此可以在一次生成里同时使用：

~~~text
Start frame → 控制开场画面
Character reference → 控制人物身份
Video reference → 控制运镜
Text → 控制当前动作与限制
~~~

这比笼统写“参考这些素材”稳定得多。

---

## 二十三、一个 Clip 尽量只有一个主动作 + 一个主要 Camera Move

前文已经强调“一个镜头一个主动作”。

Magnific 的实测经验还补充了第二条：

> **一条 Clip 尽量只放一个主要运镜。**

例如不要在 5 秒里同时要求：

- push-in；
- orbit；
- crane up；
- whip pan；
- rack focus；
- 最后再 pull-back。

这种堆叠很容易导致：

- 运动变形；
- 镜头意图互相覆盖；
- 主体被拉扯；
- 物理不稳定；
- 节奏失控。

更稳妥的处理：

~~~text
Clip 1：slow push-in
Clip 2：tracking
Clip 3：arc / orbit
~~~

如果要组合多个运动，应让它们具有明确的先后关系和充分时长，而不是当作“镜头运动关键词包”。

---

## 二十四、摄影机动作词汇应该直接进入 Prompt

Magnific Handbook 总结了十二类常用镜头语言。它们可以作为 Shot Table 的 Camera 字段词汇库：

| 镜头运动 | 视觉作用 |
| --- | --- |
| Push-in | 向主体靠近，增加亲密感或压力 |
| Pull-back | 后退揭示空间，适合结尾、孤立或尺度 |
| Pan | 机位固定，水平旋转 |
| Tilt | 垂直旋转 |
| Tracking | 摄像机与主体共同移动 |
| Arc / Orbit | 围绕主体运动 |
| Crane / Jib | 垂直升降或大尺度扫过 |
| Zoom | 机位不动，焦段变化 |
| Dolly zoom | 摄像机与焦段反向变化，制造空间畸变感 |
| Whip pan / Crash zoom | 极快运动，适合冲击、喜剧或转场 |
| Handheld | 轻微自然晃动，增加临场感 |
| Static + angle | 静态机位配合低机位、高机位、Dutch、俯拍等 |

需要注意：

- 人物 Orbit 角度过大时更容易出现身份和空间漂移；
- Handheld 最好明确 subtle，否则模型可能过度抖动；
- 快速镜头会暴露更多生成错误；
- “slow”通常比“fast”更容易保持稳定。

这些属于生成视频中的经验性制作规律，不是传统摄影语言本身的定义限制。

---

## 二十五、镜头数字是速记，真正需要写的是“可见结果”

和 AI 图像一样，视频模型不一定严格模拟真实镜头物理。

因此：

- 24mm；
- 35mm；
- 85mm；
- f/1.8；

可以作为摄影语义速记，但不应单独承担控制。

例如：

> 85mm portrait lens

最好同时写：

> 背景明显压缩并融入柔和虚化，主体面部保持自然比例。

> f/1.8

最好同时写：

> 极浅景深，只有眼睛和前脸清晰，背景柔和融化。

真正需要精确理解光学时，应回到 [[景深与镜头控制：焦距、光圈、距离、画幅与超焦距]]。

---

## 二十六、场景规则：模型只能执行“看得见、听得到”的东西

### 1. 动作写意图与结果，不要写逐关节生物力学

视频模型通常更适合：

> 后旋踢命中对方。

而不是：

> 前臂旋转 45°，肩关节……随后髋部……

过度微观的生物力学描述反而容易互相冲突。

复杂道具操作例外：对于抓握、倾倒、按钮等可见机械动作，仍然可以写清楚手、方向和接触关系。

### 2. 情绪要写成物理表现

不要只写：

> 她很愤怒。

可以写：

- 下颌收紧；
- 鼻翼扩张；
- 说话时停顿；
- 视线偏开后再回来；
- 手指收紧。

即：

> **情绪标签用于导演理解，可见行为用于模型执行。**

### 3. 只写摄像机能看到或麦克风能听到的东西

“房间里有雪松气味”“他在想起童年”不会直接变成画面。

应该翻译成：

- 工作台上有雪松刨花；
- 光束中漂浮木屑；
- 他停下动作，看向旧照片。

### 4. 离开画面的物体不要默认会回来

连续单镜头里，一旦重要主体完全 exit frame，模型可能无法稳定保持它的状态。

如果后续仍需要它，优先：

- 保持局部可见；
- 切镜后重新建立位置；
- 或明确用新镜头重新介绍。

### 5. 重要可辨认角色数量要控制

Magnific 的经验规则是：

> 同一段跨镜头连续跟踪的重点人物超过约三名后，身份交换风险会明显上升。

这不是所有模型的硬上限，但值得作为高风险提示。

群众可以保持泛化描述；真正需要持续识别的人应明确资产化。

### 6. 镜子会显著提高空间几何难度

正面把镜面反射作为画面主信息时，模型必须同时维持：

- 实体空间；
- 镜中反向空间；
- 人物与道具映射；
- 光线对应。

因此更稳妥的是：

- 斜角拍镜子；
- 不让镜面承担关键叙事；
- 或把镜中画面单独作为高风险镜头处理。

### 7. 每次 Cut 后重新建立空间

重新明确：

- 人物左右位置；
- 面向方向；
- Camera side；
- eyeline；
- 道具状态。

这与传统 180° 规则一致：如果没有叙事目的，不要让摄像机随意跨越动作轴线。

## 二十七、五种镜头“接缝”决定多 Clip 如何连接

一部长视频不是一条 Prompt，而是一串镜头之间的 seam。

### 1. Frozen handoff

Clip N 的最后一帧成为 Clip N+1 的第一帧。

适合：

- 真正无缝续写；
- 同一动作继续；
- 同一空间延长。

关键是：

> 下一镜必须基于实际接受的最后一帧，而不是原计划最后一帧。

### 2. Action bridge

动作在上一镜开始，在下一镜从新角度完成。

例如：

~~~text
Clip 1：手开始抬起杯子
Clip 2：从侧面看到杯子被送到嘴边
~~~

两条 Prompt 中都要重述：

- 动作是什么；
- 方向是什么；
- 接触关系是什么。

### 3. Match cut

两个镜头共享：

- 形状；
- 位置；
- 颜色；
- 运动方向；

但场景改变。

模型需要同时知道两个镜头之间“押韵”的元素。

### 4. Portal

镜头推进到一个完全填满画面的物体，然后从另一空间出来。

例如：

- 门；
- 蒸汽；
- 眼睛；
- 黑暗；
- 屏幕。

它很显眼，使用过多会变成套路。原资料建议整片谨慎使用。

### 5. Hard cut

干净断开。

当两个镜头没有必须保持的空间或运动连续性时，它往往比强行“无缝”更合理。

## 二十八、对白控制：一句话、一个说话者、一个表演动作

原资料对带原生音频模型的建议是：

1. 对白加引号；
2. 明确是谁说；
3. 描述说话方式；
4. 每个 beat 尽量只有一个说话者；
5. 明确 no subtitles，避免自动烧录字幕；
6. 如果后期会配乐，可明确 no music，只保留环境与音效。

例如：

~~~text
近景。咖啡师把杯子推过柜台。
她看向镜头，温和地说：“小心，很烫。”
背景只有咖啡馆人声和咖啡机蒸汽声。
无音乐，无字幕。
~~~

真正影响表演的是：

- 停顿；
- 重音；
- 声音状态；
- 眼神；
- 小动作。

而不是“高级表演”“电影级演技”这样的泛化词。

---

## 二十九、多动作镜头可以用 Beat Sheet，但要遵守版本边界

Magnific 在 Seedance 2.5 示例中使用：

~~~text
00:00 静止
00:02 主体开始上升并旋转
00:04 稳定，轮廓光扫过
~~~

这样可以防止模型把所有动作挤在第一秒。

这与前文“Seedance 2.0 不宜过度依赖精确 timestamp”并不矛盾，因为：

- 2.0 与 2.5 是不同模型线；
- 精确时间控制能力存在版本差异；
- 时间码是否有效必须按当前模型重新测试。

长期规则应写成：

> **需要多个动作时，用明确 Beat 顺序控制节奏；是否使用精确时间码，按模型版本决定。**

---

## 三十、音频应该在生成阶段主动“减法”

如果最终还要剪辑和配乐，生成时不要让模型自动塞入不可控音乐。

一个通用生产策略：

~~~text
生成阶段：
- 对白
- SFX
- 环境声
- No music
- No subtitles

后期阶段：
- 音乐
- 最终字幕
- 混音
~~~

这样做的原因：

- 生成音乐会限制后期节奏；
- 烧录字幕难以干净移除；
- 后期工具对音乐和字幕控制远高于生成模型。

这不是说所有项目都必须无音乐，而是：

> **如果音乐与字幕不是当前镜头生成的核心变量，就不要提前把它们锁死。**

---

## 三十一、强大的视频编辑往往从“第一帧编辑”开始

原资料给出了一条非常值得保留的跨模型工作流：

~~~text
已有视频
   ↓
提取第一帧
   ↓
用图像编辑模型精确修改第一帧
   ↓
把修改后的第一帧作为新 Start Frame
   +
把原视频作为 Motion Reference
   ↓
重新生成同样运动的新版本
~~~

例如：

- 原视频：白色鞋；
- 图像编辑：把鞋改成黑色，其他全部保持；
- 视频模型：重复原视频的相同 orbit、节奏和构图。

为什么有效：

- Start Frame 负责“画面内容”；
- Video Reference 负责“怎么运动”。

这把一个困难的视频编辑拆成：

> **图像级内容控制 + 视频级运动控制。**

它和 [[参考视频动作迁移与白模控制]] 的“把外观与运动分离”是同一套思想。

---

## 三十二、一张场景图可以生成“虚拟勘景覆盖”

原资料给出的另一个实用方法是：

1. 先有一张高质量场景图；
2. 把它作为视频起始帧；
3. 让摄像机慢速移动、旋转；
4. 在每一个方向停留一个 beat；
5. 从视频中提取不同角度的稳定帧。

这些帧可以继续作为：

- 新镜头 Start Frame；
- 场景 Reference；
- 背景板；
- 构图草图。

与分别独立生成每一个角度相比，这种做法的优势是：

- 灯光来自同一连续渲染；
- 场景结构更容易保持；
- 人群、建筑和空间状态更一致。

Prompt 不应只说“给我多个角度”，而应明确：

~~~text
向右旋转 → 停
向前缓慢推进 → 停
向左旋转 → 停
180° 转身 → 停
~~~

真正有价值的是**可提取的停顿帧**。

---

## 三十三、角色身份之外，还要建立“表演参考”

角色 Sheet 只能固定：

- 脸；
- 身材；
- 服装；
- 外观。

但它不能固定：

- 怎么说话；
- 怎么停顿；
- 怎么看人；
- 紧张时怎么动；
- 情绪如何转化为身体动作。

因此原资料提出“audition / self-tape”工作流：

1. 在简单房间拍一条短表演测试；
2. 中近景、眼平机位、背景简单；
3. 只说一句有潜台词的短对白；
4. 为声音给出最多三种表演品质；
5. 指定一个声音细节 + 一个身体细节；
6. 生成 2–3 个不同版本；
7. 选中一个；
8. 后续所有场景把这条视频作为 performance reference。

例如：

- voice：克制、受伤、几乎温柔；
- micro-action：先低头，再抬眼；
- vocal beat：第二个关键词声音轻微断一下。

于是一个角色拥有两套核心资产：

~~~text
Character Sheet → 外观身份
Performance Reference → 表演身份
~~~

这比每个镜头重新抽“演技”更稳定。

---

## 三十四、模型路由是版本快照，导演方法才是长期知识

原资料 2026-07 的视频模型表把：

- Seedance 2.5；
- Kling 3.0 Omni；
- Happy Horse 1.1；
- Gemini Omni Flash；

按当时任务能力进行分工。

其中可长期保留的是“按任务路由”的思想：

- 谁更适合生成；
- 谁更适合编辑；
- 谁更适合角色连续性；
- 谁更适合产品文字；
- 谁更适合低成本迭代。

但不要把“某模型永远最好”写死。

截至 2026-10-03：

- ByteDance Seed 官方仍确认 Seedance 2.5 为 30 秒长叙事、参考与编辑模型，并支持多轮延长；
- Magnific 后续 8–9 月又新增了更多模型与制作流程；
- 模型能力、分辨率、价格和参考输入上限都可能快速变化。

因此：

> **长期知识保存导演语法、资产管理、参考权、接缝、表演与返工；模型数值和排名每次生产前重新核验。**
