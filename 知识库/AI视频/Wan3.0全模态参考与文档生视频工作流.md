# Wan3.0全模态参考与文档生视频工作流

## 这套能力解决什么问题

Wan3.0 的核心变化，不只是“把单次生成时间拉长到 30 秒”，而是把视频生成从传统的：

```text
文字 → 视频
图片 → 视频
```

扩展成：

```text
文字
+ 图片
+ 视频
+ 音频
+ 文档
+ 网页
        ↓
统一理解
        ↓
有声视频
```

这意味着视频模型开始承担一种新的角色：

> **把多种信息源重新组织成一段完整的视听表达。**

它不只是“生成画面”，也开始处理：

- 角色和产品参考；
- 动作和运镜参考；
- 音色和音乐参考；
- PPT / PDF / Word / Excel / Markdown 等文档；
- 公开网页；
- 首帧 / 首尾帧；
- 视频编辑与延长；
- 原生台词、BGM 与音效。

---

## 一、当前可确认的官方能力

截至 2026-10-03，阿里云百炼公开的 Wan3.0 视频模型包括：

- `wan3.0-video`
- `wan3.0-video-prime`（优速版）

核心规格：

- 单次生成时长：2–30 秒；
- 输出：480P / 720P / 1080P；
- 输出帧率：30fps；
- 支持原生有声视频；
- 可原生生成台词、BGM 和音效；
- 支持首帧 / 首尾帧控制；
- 支持视频编辑和视频延长；
- 支持多模态参考；
- 支持文件和公开网页作为输入。

Wan3.0 是 All-in-One 模型，不需要因为“文生视频 / 图生视频 / 参考生视频”切换不同模型 ID。

---

## 二、参考素材不是越多越好，而是要先明确职责

Wan3.0 的参考素材可以承担多种控制职责。

### 图片

适合控制：

- 人物身份；
- 产品外观；
- 服装；
- 道具；
- 场景；
- 风格；
- 关键帧。

### 视频

适合控制：

- 动作；
- 表情节奏；
- 运镜；
- 特效；
- Blocking；
- 时间节奏；
- 场景动态。

### 音频

适合控制：

- 音色；
- 台词；
- 音乐；
- 节奏；
- 情绪；
- 环境氛围。

### 文档 / 网页

适合提供：

- 产品信息；
- 课程内容；
- 汇报结构；
- 数据；
- 品牌信息；
- 知识内容；
- 叙事素材。

因此，多模态参考真正需要的不是“多上传”，而是：

> **明确每一个参考素材到底负责什么。**

这与 [[AI视频导演式Prompt编译：镜头表、参考权、连续性与返工]] 中的 reference authority 原则一致。

---

## 三、官方素材上限与组合规则

Wan3.0 当前官方 API 规则包括：

### Reference Image

- 最多 10 张。

### Reference Video

- 最多 5 段；
- 所有参考视频总时长不超过 15 秒。

### Reference Audio

- 最多 5 段；
- 所有参考音频总时长不超过 15 秒。

### File

一次最多 1 个文件。

支持：

- docx / doc；
- xlsx / xls；
- pptx / ppt；
- pdf；
- txt；
- md。

### Link

一次最多 1 个公开网页链接。

### 重要互斥关系

`reference_image / reference_video / reference_audio / file / link`

与：

`first_frame / last_frame`

属于不同输入模式，不能任意混用。

因此设计工作流前，应先决定：

> 这一条生成到底是“参考素材驱动”，还是“首尾帧驱动”。

---

## 四、参考素材在 Prompt 里必须显式引用

Wan3.0 官方推荐直接使用：

- 图1；
- 图2；
- 视频1；
- 视频2；
- 音频1；

来引用素材。

图片、视频、音频分别独立编号。

例如：

```text
图1控制人物外观，
图2控制服装，
视频1控制动作和运镜，
音频1控制角色音色。
```

这比：

> “请综合参考所有素材”

清楚得多。

同一素材也可以承担多个职责，但最好明确写出来。

---

## 五、参考时最好同时写“借什么”和“不借什么”

例如只想参考运镜：

```text
参考视频1的运镜方式，
场景和人物不要继承视频1。
```

只想参考风格：

```text
仅参考图2的色调与光影，
不要继承其中人物。
```

只参考动作：

```text
视频1负责动作轨迹，
人物身份以图1为准。
```

这样可以减少：

- 身份串位；
- 场景污染；
- 风格误迁移；
- 服装变化；
- 角色复制。

---

## 六、Wan3.0与Seedance 2.0的一个重要Prompt差异：时间戳

[[AI视频导演式Prompt编译：镜头表、参考权、连续性与返工]] 中记录过：

> Seedance 2.0 更适合镜头顺序，不应依赖精确 timestamp。

Wan3.0 不一样。

阿里官方明确推荐：

```text
分镜1（00:00-00:03）
分镜2（00:03-00:06）
分镜3（00:06-00:10）
```

也支持：

- 只写镜头编号；
- 只写时间段；
- 编号 + 时间段。

官方建议一个分镜通常控制在约 2–5 秒。

因此：

> **不同视频模型的 Prompt 控制语法不能机械复用。**

导演方法可以通用，但模型自己的时间控制机制要单独核验。

---

## 七、一个完整Wan3.0 Prompt可以拆成七个部分

官方给出的完整结构可以整理为：

```text
总体描述
+
参考素材引用
+
分镜 / 时间段
+
主体 / 场景 / 动作 / 摄影
+
台词
+
音效 / BGM
+
风格 / 情绪
+
负向清单
```

不是每一个 Prompt 都必须全部写满。

原则是：

> 想控制的就写，不需要控制的就省略。

这比无限堆叠形容词更有效。

---

## 八、总体描述负责“全片规则”

总体描述适合一次定义：

- 主题；
- 叙事视角；
- 整体节奏；
- 视觉风格；
- 情绪走向；
- 核心场景；
- 整体声音策略。

例如：

```text
15秒商业广告，
节奏由克制铺垫转向快速爆发，
黑银冷色调，
写实电影风格。
```

后续各镜头不用反复重写全部全局规则。

---

## 九、分镜负责“局部状态变化”

每一个分镜至少描述：

- 谁；
- 在哪里；
- 做什么；
- 镜头怎么拍；
- 镜头结束时到达什么状态。

例如：

```text
分镜2（00:04-00:08）：
中近景，50mm感，
人物从桌边起身，
走向窗边，
摄影机缓慢横移跟随。
```

如果希望硬切、叠化或无缝衔接，也应写明。

---

## 十、单镜头和多镜头应明确区分

### 单镜头

可以直接写：

- 生成单镜头；
- 一镜到底；
- Generate single shot.

并集中描述一个连续动作。

### 多镜头

使用：

- 镜头序号；
- 时间段；
- 明确转场。

不要让模型自己判断什么时候切镜。

---

## 十一、台词需要显式写角色和内容

推荐：

```text
角色A低声说：“……”
角色B回答：“……”
```

多人对话最好逐句标明说话人。

需要口型时：

```text
口型同步
```

如果使用音色参考：

```text
音色参考音频1
```

### 不想要台词时一定要明确

```text
无台词
```

否则模型可能自行补充对白。

---

## 十二、声音也需要明确“是否交给模型自由发挥”

Wan3.0 会自动生成环境音、动作音、台词和 BGM。

因此有三种策略。

### 完全放开

不写，让模型自动决定。

### 部分控制

明确：

- 某段音乐；
- 某个音效；
- 哪个时间点发生。

### 完全关闭某一层

例如：

```text
无背景音乐，
只保留环境音与动作音。
```

这对商业片、对白片和后期要重新配乐的项目很重要。

---

## 十三、负向清单不是越长越好

官方提示词指南明确建议：

> 不希望出现什么就写什么，不需要为了完整而凑数。

常见负向控制包括：

### 身份

- 不要换脸；
- 不要服装变化；
- 不要人物身份漂移。

### 身体

- 不要肢体扭曲；
- 不要多余手指；
- 不要穿模。

### 空间

- 不要轴线混乱；
- 不要人物位置突变；
- 不要多余人物。

### 摄影

- 不要频繁切镜；
- 不要持续抖动；
- 不要夸张旋转。

### 声音

- 无台词；
- 无人声旁白；
- 无背景音乐。

因此负向清单应该来自：

> **你真正担心的失败模式。**

而不是复制一份万能 Negative Prompt。

---

## 十四、文档生视频真正改变了什么

这是 Wan3.0 最值得长期关注的能力之一。

传统文档转视频往往需要：

```text
PPT / PDF
   ↓
人工提炼
   ↓
写脚本
   ↓
拆镜头
   ↓
生成素材
   ↓
剪辑
```

Wan3.0 开始支持：

```text
PPT / PDF / Word / Excel / Markdown
       ↓
模型理解文件内容
       ↓
结合 Prompt 重新组织
       ↓
视频
```

这并不代表模型会自动理解“什么最重要”。

Prompt 仍然应该告诉模型：

- 视频面向谁；
- 核心信息是什么；
- 哪些数据必须保留；
- 哪些内容可以省略；
- 希望什么叙事方式；
- 需要多长；
- 是否需要旁白；
- 是否需要商业广告感 / 教学感 / 汇报感。

---

## 十五、文档输入适合的典型场景

### PPT → 产品广告

将：

- 产品结构；
- 卖点；
- 参数；
- 产品图；

直接作为信息源。

Prompt 决定最终变成：

- 产品发布片；
- 电商广告；
- 概念宣传片。

### Excel → 数据汇报视频

可以从表格中读取：

- KPI；
- 趋势；
- 对比；
- 排名。

再要求用 Motion Graphics 或商务风格表达。

### PDF → 知识科普

适合：

- 教材；
- 报告；
- 白皮书；
- 研究材料。

但必须限定：

> 只取指定主题，不要让模型试图在 30 秒内“概括整个文件”。

### Markdown / 文本 → 脚本化视频

适合：

- 已整理知识；
- 产品说明；
- 剧情梗概；
- 内容脚本。

这和 NoIT 本身的 Markdown 知识体系有潜在连接：未来可以把已经整理好的知识主题直接转成视频表达素材。

---

## 十六、网页生视频的意义

Wan3.0 还支持公开网页链接作为参考。

这意味着可以：

```text
产品官网
→ 读取产品信息
→ 生成产品介绍视频
```

或：

```text
百科 / 公共知识页面
→ 读取内容
→ 生成科普视频
```

但它只适合：

- 可公开访问；
- 页面结构清晰；
- 内容来源可靠；

的网页。

需要登录、动态权限或隐私数据的页面，不应假设模型可以读取。

---

## 十七、文件/网页输入不能替代内容判断

模型能够“读文档”，不代表它知道：

- 哪一页最重要；
- 哪个指标最关键；
- 哪个观点不能删；
- 哪个内容必须核验；
- 哪一段不应该公开。

因此真正稳定的文档生视频流程应该是：

```text
原始文件
   ↓
定义视频目标
   ↓
指定核心信息
   ↓
告诉模型信息优先级
   ↓
决定镜头和时间预算
   ↓
生成
   ↓
人工核对事实
```

特别是：

- 数字；
- 产品参数；
- 金额；
- 法律信息；
- 医疗信息；
- 研究结论；

不应因为模型生成了视频就自动认为准确。

---

## 十八、30秒能力改变的是“一个生成单元”的规模

Wan2.x / Seedance 等较短生成模型常常要求：

> 一个生成 = 一个镜头或少量镜头。

Wan3.0 的 30 秒能力让一个生成单元可以承担：

- 4–8 个镜头；
- 完整广告；
- 一段产品介绍；
- 一段短剧情；
- 一段教学演示；
- 一段数据汇报。

但：

> 30 秒并不等于无限信息容量。

如果同时要求：

- 十几个角色；
- 十几个复杂动作；
- 很长对白；
- 多次场景切换；
- 大量 UI / 字幕；

仍然可能出现拥塞。

因此仍然需要做信息预算。

## 二十、一个可复用的Wan3.0工作流

```text
明确视频目标
   ↓
选择输入模式
   ↓
准备参考图 / 视频 / 音频 / 文档 / 网页
   ↓
为每个素材分配职责
   ↓
写总体描述
   ↓
拆镜头和时间段
   ↓
写动作 / 摄影 / 台词 / 音频
   ↓
写必要负向约束
   ↓
生成
   ↓
核对事实与连续性
   ↓
针对单一失败点调优
```

核心不是“Wan3.0可以塞很多素材”，而是：

> **把不同信息源转化成一个明确、有时间结构、有控制权分工的视听计划。**
