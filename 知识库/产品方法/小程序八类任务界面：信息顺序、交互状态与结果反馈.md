# 小程序八类任务界面：信息顺序、交互状态与结果反馈

## 先根据任务分类，而不是统一套 UI 模板

用户进来要完成什么、什么条件影响下一步、提交后怎么确认和找回，决定界面信息顺序。八类页面即使都用卡片，主要交互也完全不同。以下案例是原作者在 2026 年观察的页面，不保证当前版本仍相同。

## 01 工具服务型｜快递100

任务：查件或寄件 → 场景选择（普通寄件、大件、退货）→ 地址/物品输入 → 服务比较 → 订单状态。首屏优先常用任务，不让运营广告盖过办事入口。两列宫格用于入口，单列表单用于按步骤填资料。地址复用、粘贴与识别减少重复输入，仍须核对。起步价、最终报价、预约取件、已揽件不能混用。

## 02 预约服务型｜国家博物馆

任务：日期 → 展览或服务 → 时段及名额 → 人员 → 结果。选项前后有依赖，日期改变时清除已无效下游选项。可选、已选、约满、未开放、已过期用文字和视觉共同标示。确认提交时重新核验可用性。成功页应说明预约时间、地点、人数和记录、取消或修改方式。

## 03 零售电商型｜优衣库

任务：活动浏览/分类/搜索 → 筛选 → 商品列表 → 规格/库存 → 配送 → 下单。人群分类和品类分类分两层；分类宫格适合图片，商品信息密集则按需要单列或双列。商品卡统一图片比例、标题、售价；SKU 是具体颜色尺码组合，应区分选中、缺货、不可选。购买前明确当前配置、价格与履约方式。

## 04 内容消费型｜小宇宙

任务：发现节目 → 看节目结构 → 选单集 → 看摘要、时长、时间戳 → 播放与续听。精选用大卡，长标题排行用单列。节目和单集是不同层级，不能混淆。迷你播放器保持当前单集、暂停/播放、进度信息，允许在浏览中继续收听。加载失败与恢复上次进度也是核心功能。

## 05 餐饮点单型｜星巴克

任务：门店或地址及堂食/自提/外送 → 餐品与杯型/甜度等规格 → 优惠条件 → 付款 → 备餐、取餐、配送。门店营业和库存会限制选择。菜单多时可左侧类目、右侧菜品；底部购物车显示金额但不能挡正文。会员价、普通价和额外付费月卡分开写。付款成功不等于餐品已经制作完成。

## 06 教育学习型｜影视飓风

任务：我的课程/课程广场 → 课程 → 单元 → 课时 → 播放、练习与恢复。购买入口与已有课程继续学入口分区。课时列表标明当前、未学、完成和时长，保留上次播放位置。学习进度不同于掌握程度，后者需要练习或评估。处理好长课程标题和视频失败重试。

## 07 AI任务型｜WorkBuddy

任务：示例引导 → 文本、语音或附件发起任务 → 执行、补充、失败或完成 → 识别并使用产物。任务建议写用户能做到什么，而不是内部技术术语。展示清楚待处理、进行中、等待材料及完成状态。多种文件（文档、演示文稿、图片）按主成果和辅助成果组织，允许预览、编辑、保存、导出。通知将用户带回具体任务，不能代替结果页。

## 08 社区互动型｜兔小巢

任务：帮助与帖子发现 → 看帖、互动 → 发帖、投票 → 收到回复 → 查看处理进度。帮助文档与社区讨论不同。投票量代表参与热度，已受理、处理中、已完成代表业务状态，不该互相替代。发帖失败要能恢复编辑，通知可跳转至具体回复。

## 共用模块与上线前检查

- Tabs 是区域内内容切换，TabBar 是一级导航。
- 会员资产、领取资格、积分门槛和实际优惠必须说明清楚。
- 空状态写原因和下一步；底部按钮避免遮盖安全区与最后一项。
- 为长标题、无结果、无权限、断网、重复提交、过期状态提供反馈。
- 用真实任务从入口走到结果，而不是只看静态图。
- WXML 负责结构、WXSS 负责样式、JS/TS 负责行为；技术分层无法代替业务依赖和状态设计。
