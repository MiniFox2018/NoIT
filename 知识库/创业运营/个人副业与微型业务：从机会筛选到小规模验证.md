# 个人副业与微型业务：从机会筛选到小规模验证

## 核心判断

“在家做什么能赚钱”不是一个适合用项目清单回答的问题。

真正需要解决的是：

> **哪一种收入机制与自己的技能、现金、时间、风险承受能力和获客条件匹配，并且能用很小的成本先验证？**

六个周在《如何蜗居赚钱：探索多种可能性》中列出了：

- 微信小游戏；
- 家政小程序；
- 写小说；
- 猪八戒接单；
- 电商；
- 投资理财；
- 内容创作。

这份资料最值得保留的不是 2025 年的平台费用、收入数字和规则，而是它暴露出的几类完全不同的赚钱机制。

如果把这些机制混在一起，只问“哪个更赚钱”，很容易做错决策。

---

## 一、先分清：这些事情实际上不是同一种生意

可以把原文的七类路径重组为六种模式。

| 模式 | 原文对应 | 本质 |
| --- | --- | --- |
| 数字产品 | 微信小游戏 | 先投入开发，再靠大量用户或付费重复变现 |
| 双边服务平台 | 家政小程序 | 同时解决供给、需求、信任、履约和结算 |
| 内容/IP | 小说、内容创作 | 持续生产内容，积累读者、分发与知识产权 |
| 自由职业 | 猪八戒接单 | 用个人技能直接换项目收入 |
| 商品经营 | 电商 | 选品 + 供应链 + 流量 + 履约 |
| 资本配置 | 投资理财 | 用本金承担市场风险，获取资产回报 |

它们的：

- 风险；
- 现金流；
- 时间结构；
- 能力要求；
- 扩张方式；

完全不同。

第一步不是选一个“热门方向”，而是先确定：

> 自己到底想经营业务、出售技能、生产内容，还是配置资本？

---

## 二、用 9 个维度筛选机会

任何副业都可以先回答这 9 个问题。

### 1. 用户是谁

不要写：

- 所有人；
- 年轻人；
- 宝妈；
- 企业。

要写到一个可以找到的具体群体。

### 2. 解决什么问题

问题是否：

- 真实；
- 高频；
- 有明显不满；
- 已经有人为替代方案付钱或付出大量时间？

### 3. 第一笔收入怎么来

必须能画出：

~~~text
谁
→ 因为什么
→ 在什么时候
→ 为什么愿意付多少钱 / 付出什么
~~~

如果连第一笔钱从哪里来都说不清，商业模式还没有建立。

### 4. 获客从哪里来

问：

- 第一批 10 个用户在哪里？
- 能不能直接联系到？
- 获客依赖付费广告还是自然渠道？
- 平台推荐一停，业务是否归零？

### 5. 交付成本

每多一个客户，是否必须投入等比例人工？

如果是，它更接近：

> 自由职业 / 服务。

如果可以通过：

- 软件；
- 内容；
- 模板；
- SOP；
- 供应链；

重复交付，它更容易形成资产。

### 6. 前期资金

需要：

- 0 库存；
- 服务器；
- 营销；
- 注册主体；
- 采购；
- 人员；

多少不可逆投入？

早期越不确定，越应该降低不可逆成本。

### 7. 合规与平台依赖

平台的：

- 主体要求；
- 支付；
- 广告；
- 分成；
- 内容审核；
- 税务；

都可能变化。

平台规则不能靠旧博客永久记忆。

### 8. 信任门槛

用户交给你的东西越重要：

- 家门钥匙；
- 钱；
- 身份信息；
- 儿童服务；
- 长期合同；

信任基础设施越重要。

### 9. 能否形成复利

做完一次后，有没有留下：

- 代码；
- 模板；
- SEO；
- 品牌；
- 客户关系；
- 作品；
- 邮件名单；
- 数据；
- SOP？

如果什么都没留下，第二次仍从零开始。

## 三、微信小游戏：它不是“写完就有广告收入”

原文最初把小游戏看成一种可能的居家赚钱方式，但进一步调研后，实际上暴露了四个不同问题：

~~~text
产品
+ 开发
+ 分发
+ 变现
~~~

少一个都不成立。

### 1. 产品

需要：

- 核心玩法；
- 低学习成本；
- 反馈；
- 关卡 / 成长；
- 留存理由。

“技术上能做出来”与“有人持续玩”是两个问题。

### 2. 开发

需要根据游戏类型处理：

- 2D / 3D；
- 状态与关卡；
- 动画；
- 音频；
- 后端；
- 排行榜；
- 性能；
- 兼容性。

原文列过 Cocos Creator、LayaAir、Egret、Three.js 等技术选项。

这类工具链变化很快，因此 NoIT 不把 2025 年的列表固化成当前推荐。

真正长期有效的是：

> 先选最能快速验证玩法的技术，而不是先选最“专业”的技术。

### 3. 分发

小游戏最容易被低估的是：

> 用户为什么会知道它？

需要验证：

- 社交传播；
- 内容渠道；
- 搜索；
- 现有流量；
- 广告；
- 联运；
- 平台推荐。

没有分发，只完成开发并不构成业务。

### 4. 变现

广告、内购、会员、支付能力都受到平台当前规则和开发者主体条件影响。

原文中的 2025 年规则不能直接当作 2026 年现行标准。

正式上线前必须重新核验微信官方：

- 主体资格；
- 广告接入；
- 内购 / 支付；
- 游戏资质；
- 内容审核；
- 未成年人相关要求；
- 税务。

### 5. 更合理的验证方式

不要先做一个“完整游戏”。

可以：

~~~text
核心玩法 demo
→ 找真实玩家试玩
→ 测是否愿意重复玩
→ 测是否愿意分享
→ 再增加关卡 / 商业化
~~~

首先验证：

> 游戏好不好玩。

不是首先验证：

> 广告能不能接。

## 四、家政小程序：先做服务，再做平台

原文识别出的家政行业痛点值得保留：

- 供需信息不对称；
- 服务质量不稳定；
- 信任；
- 匹配效率；
- 结算；
- 评价；
- 资质。

但这里最危险的误区是：

> 一看到行业低效，就先做一个小程序。

技术并不是双边市场最难的一层。

真正难的是：

~~~text
有雇主但没有服务者
→ 没人用

有服务者但没有订单
→ 服务者离开

订单来了但质量不可控
→ 信任崩溃
~~~

### 1. 第一阶段：人工跑通

先用：

- 微信；
- 表单；
- 电话；
- Excel；
- 人工派单；

跑完整链路：

~~~text
获客
→ 需求确认
→ 匹配
→ 服务
→ 付款
→ 售后
→ 评价
~~~

如果人工都跑不通，软件通常只会自动化一个还没成立的流程。

### 2. 第二阶段：找到最重复的摩擦

例如：

- 重复录资料；
- 排班；
- 派单；
- 报价；
- 结算；
- 客服问题。

再产品化。

### 3. 第三阶段：建立信任系统

家政平台不是普通信息目录。

可能需要：

- 身份与资质核验；
- 保险；
- 服务标准；
- 订单证据；
- 支付保障；
- 投诉；
- 退款；
- 争议处理；
- 用户隐私保护。

信任系统做不好，增加流量只会放大问题。

### 4. 收入方式只是结果

原文列出：

- 中介费；
- 平台服务费；
- 增值服务；
- 培训；
- 广告。

这些只是可能的收费模型。

先验证：

> 用户是否真的愿意通过你完成交易。

再讨论从哪里抽成。

## 五、写小说：本质是长期内容产品

小说与软件的共同点比看起来多。

都需要：

~~~text
目标受众
→ 核心价值
→ 持续交付
→ 留存
→ 分发
→ 反馈
→ 迭代
~~~

### 1. 核心资产是作品，不是平台收益公式

原文包含：

- 阅读量；
- 平台分成；
- 完读率；
- 某些字数节点；
- 收益案例。

这些高度依赖：

- 平台；
- 时间；
- 题材；
- 推荐机制；
- 合同。

因此不应固化为长期收入预测。

长期有效的是：

- 读者是否愿意持续读；
- 哪个章节开始流失；
- 哪个角色 / 冲突真正有效；
- 更新是否稳定；
- 是否形成可继续复用的 IP。

### 2. AI 可以辅助，但不要让作品失去作者控制

AI 适合：

- brainstorm；
- 资料整理；
- 结构检查；
- 找逻辑漏洞；
- 润色候选；
- 生成备选情节。

作者仍需要控制：

- 人物弧；
- 世界观；
- 主题；
- 叙事声音；
- 原创性；
- 版权风险。

“更快生产文字”不等于“更好故事”。

### 3. 作品数据用于诊断，不用于迎合每一个短期波动

可以观察：

- 开篇留存；
- 章节完成；
- 评论；
- 收藏；
- 追更；
- 付费转换。

但创作不能每出现一次短期数据变化就重写方向。

需要区分：

> 稳定趋势 vs 随机波动。

## 六、自由职业平台：最快产生现金流，但很容易变成第二份工作

猪八戒只是原文的一个具体平台。

长期知识不依赖它。

自由职业模型的核心是：

~~~text
技能
→ 项目
→ 交付
→ 评价 / 案例
→ 更好的项目
~~~

### 优势

- 启动成本低；
- 可以较快验证市场；
- 很快获得真实客户问题；
- 很适合建立第一笔非工资收入。

### 难点

原文识别出的风险仍然成立：

- 竞争激烈；
- 收入不稳定；
- 客户频繁改需求；
- 项目周期不确定；
- 个人时间成为瓶颈。

### 最关键的是 Scope

接单前至少确认：

- 做什么；
- 不做什么；
- 交付物；
- 时间；
- 修改次数；
- 验收；
- 付款节点。

很多自由职业亏损不是因为报价太低，而是：

> 边界没有定义。

### 从自由职业走向资产

当相同需求反复出现时，可以逐步变成：

~~~text
定制服务
→ 标准服务包
→ 模板 / SOP
→ 产品化服务
→ 软件 / 内容产品
~~~

这才是从“卖时间”向可复用资产迁移。

## 七、电商：真正的系统是“选品—供应链—流量—履约”

电商看起来是“开店”，实际至少有四套系统。

### 1. 选品

不是只看什么热门，而是：

- 有明确需求吗？
- 毛利能覆盖退货、物流、平台、广告吗？
- 是否容易同质化？
- 有没有复购？
- 售后复杂吗？

### 2. 供应链

需要处理：

- 采购；
- 质量；
- 交期；
- 库存；
- 现金占用；
- 备货。

### 3. 流量

包括：

- 平台自然流量；
- 搜索；
- 广告；
- 内容；
- 达人；
- 私域。

### 4. 履约

- 发货；
- 物流；
- 退换；
- 客服；
- 售后。

原文提到“库存积压”和“平台政策变化”两个风险，这两个应该作为长期警告保留。

#### 更适合个人起步的原则

在不确定阶段：

- 更小 SKU；
- 更低库存；
- 更窄人群；
- 更短验证周期；

通常比一开始追求规模更重要。

## 八、投资理财：它不属于“经营副业”

原文把投资理财与：

- 做游戏；
- 接单；
- 电商；
- 内容；

并列为“赚钱方式”。

但从决策结构上应该明确拆开。

经营型项目的主要变量是：

- 用户；
- 产品；
- 销售；
- 成本；
- 执行。

投资的核心变量是：

- 本金；
- 风险暴露；
- 时间；
- 资产价格；
- 组合。

所以投资不是：

> 一个可以像 MVP 一样靠“多试几次”找到 PMF 的副业。

原文关于：

- 学习基础金融知识；
- 理解风险；
- 避免把全部资金押在单一资产；
- 定期复盘；

可以作为一般风险意识保留。

但具体资产配置、买卖策略和预期收益不应该从这篇创业随笔推导。

## 九、内容创作：同时是一项生产工作和分发工作

内容创作的基本能力包括：

- 选题；
- 写作 / 拍摄 / 剪辑；
- 表达；
- 视觉；
- 发布；
- 数据分析。

但真正的商业问题仍然是：

> 为什么用户会持续回来？

### 1. 找到明确的内容承诺

例如：

> 每周帮独立开发者拆一个真实增长案例。

比：

> 分享一些有意思的东西。

更容易积累稳定预期。

### 2. 建立可持续生产系统

不要只靠灵感。

可以建立：

~~~text
信息源
→ 选题池
→ 研究
→ 生产
→ 发布
→ 二次分发
→ 复盘
~~~

### 3. 不把平台流量当资产本身

原文正确指出：

> 平台算法变化会直接影响流量。

所以更稳定的内容资产包括：

- 自有网站；
- 邮件订阅；
- 可搜索内容；
- 用户社群；
- 作品库；
- 品牌。

### 4. 变现应与受众关系匹配

可能包括：

- 广告；
- 赞助；
- 付费内容；
- 咨询；
- 产品；
- 会员；
- 联盟营销。

不要在还没有稳定受众时，过早设计复杂变现体系。

## 十、不要同时启动七个项目

机会研究很容易产生一种错觉：

> 每一个方向看起来都能赚钱。

真正的风险是：

~~~text
研究 7 个方向
→ 每个都做一点
→ 没有一个获得真实反馈
→ 一直处于“准备赚钱”
~~~

更好的方式是建立机会漏斗。

### 第一步：纸面筛选

淘汰明显不匹配：

- 资金过高；
- 无法获客；
- 不具备能力；
- 合规太复杂；
- 自己根本不愿长期做。

### 第二步：低成本验证

例如：

#### 小游戏

做可玩的核心循环，不先做完整商业化。

#### 家政

先人工撮合 10 单，不先开发平台。

#### 小说

先完成一段稳定连续输出，观察真实读者留存。

#### 自由职业

先拿到一个真实付费客户。

#### 电商

先测一个窄品类，不铺几十个 SKU。

#### 内容

先连续产出一个稳定主题，而不是先设计品牌全套。

### 第三步：只给出现信号的项目追加资源

信号可以是：

- 真实付费；
- 重复使用；
- 留存；
- 推荐；
- 稳定询盘；
- 自然增长。

## 十一、用“最小可逆赌注”代替大投入

副业早期最重要的不是预测准确，而是：

> 即使判断错了，也不要损失太大。

### 可逆

- 用现成工具；
- 手工服务；
- 少量库存；
- 短周期内容实验；
- 外部渠道测试。

#### 不可逆

- 长租；
- 大量招聘；
- 大额囤货；
- 先开发半年；
- 在需求不明时注册复杂主体和采购重资产。

先做可逆动作，出现信号后再扩大不可逆投入。

---

## 十二、一张统一机会评估表

对任何新“赚钱点子”，填：

| 维度 | 问题 |
| --- | --- |
| 目标用户 | 谁会付钱？ |
| 核心问题 | 为什么现在的方式不够好？ |
| 第一个用户 | 明天去哪里找？ |
| 第一笔钱 | 如何发生？ |
| MVP | 最小验证是什么？ |
| 交付成本 | 每个新客户需要多少新增人工？ |
| 初始资金 | 错了最多损失多少？ |
| 平台依赖 | 流量、支付、账户是否被平台控制？ |
| 合规 | 主体、税务、资质、隐私、版权有什么门槛？ |
| 信任 | 用户凭什么把重要事情交给你？ |
| 留存 | 为什么第二次还会回来？ |
| 复利资产 | 做一次后留下什么？ |
| 停止条件 | 什么证据出现就应该停止？ |

最后一个问题非常重要。

没有停止条件的副业，很容易因为沉没成本持续消耗时间。

## 十三、一个个人实验组合应该怎么搭

如果目标是探索非工资收入，可以同时保留不同时间尺度，但不要同时重投入。

例如：

~~~text
短期现金流：
自由职业 / 服务

中期可复用：
产品化服务 / 小产品

长期资产：
内容 / SEO / 品牌 / 软件 / IP
~~~

这三层可以互相供给：

~~~text
接单
→ 发现高频问题
→ 形成标准服务
→ 做工具 / 模板
→ 内容分发
→ 获得更多用户
~~~

这比随机在七个方向之间跳跃更容易形成积累。

## 十四、原文中哪些内容没有直接固化为“当前事实”

《如何蜗居赚钱》发布于 2025-03-18，最后更新于 2025-06-15。

以下信息具有明显时效性，因此没有作为 2026 年主知识直接保留：

- 微信小游戏个人 / 企业主体的具体变现限制；
- 注册主体的具体费用；
- 游戏开发的人力、外包、服务器、美术成本区间；
- 某些小游戏的收入与成功判断；
- 番茄小说的具体收益示例；
- 特定字数节点对应的推荐 / 完读率规则；
- 猪八戒、淘宝、拼多多、亚马逊等平台的具体运营规则；
- 2025 年列出的开发框架是否仍应优先选择。

这些如果未来真正要执行，应直接查：

> 官方最新规则 + 当前价格 + 当前平台政策。

这是“完整吸收”与“机械保存原文”的区别：

> 保留长期有效的知识，同时明确丢弃已经不能安全当作当前事实的数字和平台细节。

## 十六、实体小店案例：先修单位经济，再用 AI 接住增长

《从亏掉70万到月销10万+，一家轻食店的AI自救》补充了一个实体小微业务的重要视角。

它的价值不在“某家店靠 AI 翻盘”的结果叙事，而在于把**渠道、单位经济、复购、履约和自动化顺序**放在一起看。

### 1. 流量不能修复负单位经济

案例早期在外卖平台上出现“做一单亏一单”的情况。无论具体数字如何，长期原则是：

> **单笔贡献为负时，更多订单可能只是更快放大亏损。**

因此在追求流量前，应先算清：

```text
实收价格
- 平台 / 支付成本
- 优惠与投放
- 食材 / 商品成本
- 包装
- 配送
- 直接人工
≈ 单笔贡献
```

如果基础结构不成立，首先要调整客群、渠道、产品、价格或履约，而不是只增加投流。

### 2. 把意外流量当需求信号，而不是复制公式

案例中的转折来自一条关店吐槽视频，评论区出现团餐需求，随后经营者转向企业、学校等机构客户。

这里不能提炼成“发一条吐槽视频就能获客”。真正可复用的是：

> **当现实反馈暴露出新的高价值需求时，及时验证，而不是执着原来的商业设想。**

流量本身不可复制，但“识别信号 → 迅速验证”可以复制。

### 3. 新渠道必须重新设计履约

团餐路径跑通后，案例继续调整产品以适配季节和场景，用套餐提高复购和订单可预测性，缩小配送半径、固定线路，并把个性化忌口与配餐规则结构化。

这说明渠道迁移不是“把原产品换个平台卖”，它会重新定义用户、购买频率、客单价、配送方式、产品组合和运营数据。

### 4. AI 应在真实瓶颈出现以后接入

订单增加后，人工汇总忌口、配餐、票据、宣传素材、视频初稿开始成为明显摩擦。

这时 AI 的价值才清楚：

> **不是为了“有 AI”，而是替换已经出现、能够描述、能够验收的重复成本。**

案例使用熟悉的协作工具承载 AI，也降低了员工学习成本。

更完整的岗位卡、路由卡和验收方法见：[[Agent Native团队：多Agent协作与人机分工]]。

### 5. 一个实体微型业务检查顺序

1. 单笔交易是否有正贡献？
2. 当前获客渠道是否值得继续？
3. 是否出现了更强的真实需求信号？
4. 复购能否被产品结构而不是促销锁定？
5. 履约半径和复杂度是否可控？
6. 哪个环节每天稳定消耗大量人工？
7. 该环节能否被规则化、自动化并验收？
8. 哪些经营判断必须继续由人负责？

### 十五、资料型数字商品：从需求发现到交付台账

新增两组实战材料——娱乐型数字商品与 K12 教务教辅资料——虽然品类不同，但底层业务结构高度一致：

~~~text
发现一个高频、具体、可搜索的问题
→ 做最小可交付产品
→ 用内容验证真实需求
→ 明确商品说明与边界
→ 人工成交与交付
→ 记录成本、退款和售后
→ 只给出现真实信号的方向追加资源
~~~

真正值得吸收的不是某个平台“几天养号、每天几条”的经验数字，而是资料型数字商品怎样从**文件堆积**升级为**可理解、可选择、可交付的产品**。

#### 1. 用户付费的不是“文件很多”，而是减少筛选和赶工成本

K12 案例把买家拆成班主任、学科老师、学校管理岗位和家长；不同人购买的并不是同一种“教育资料”。

长期原则是：

> **先按使用者和使用场景拆需求，再决定资料结构。**

用户愿意付费，往往因为产品帮助他：

- 找得到；
- 选得准；
- 改得动；
- 来得及使用。

把几万份文件直接扔进网盘，并不等于高价值交付。目录、筛选、预览、命名、格式、版本和适用场景本身就是产品的一部分。

#### 2. 资料获取必须区分“能找到”和“有权销售”

资料来源可以包括：

- 自己原创；
- 获得明确商业授权的内容；
- 正规采购且许可范围允许再销售的内容；
- 公开信息经过独立创作形成的新作品。

必须明确：

> **可下载、可阅读、已经买过，不自动等于拥有再销售权。**

同行账号、电商平台、群文件、网盘搜索、文档平台和图片反查都可以用来做**需求研究和来源发现**，但进入商品目录前应核对版权、许可和使用范围。

AI 生成也不自动消除版权、事实和质量责任。最终出售者仍需检查内容、引用、格式和可编辑性。

#### 3. 对标研究只复制“发现需求的方法”，不复制作品

对标可以记录：

- 目标人群；
- 评论区反复出现的问题；
- 定价；
- 交付形式；
- 商品详情页顺序；
- 用户抱怨；
- 封面和内容结构；
- 哪些主题被反复发布；
- 从内容到咨询再到成交的完整路径。

不要直接复制：

- 题库；
- 标题正文；
- 设计；
- 图片；
- 课件；
- 商品详情页；
- 受版权保护的资料。

研究的目标是识别：

> 什么问题正在被持续解决，用户愿意怎样购买，以及现有交付哪里不够好。

#### 4. 先做产品规格，再做文件或网页

数字商品在制作前可以先写产品规格：

- 服务谁；
- 解决什么层面的需求；
- 用户最终买到什么；
- 文件/链接是否有有效期；
- 交付流程；
- 是否收集个人数据；
- 免责声明；
- 使用限制；
- 验收标准；
- 退款与售后；
- 商业使用与托管许可。

娱乐型测试尤其要避免把娱乐、自我探索包装成医学诊断或专业心理服务。

资料型产品则要写清：

- 文件格式；
- 是否可编辑；
- 包含哪些文稿/课件/表格；
- 是否承诺更新；
- 适合哪个年级、学期、教材或场景。

#### 5. 把单份交付做成可复用模板

高复用业务不是“每来一单重做一次”。

可以把重复部分模板化：

- 产品壳；
- 配置文件；
- 目录；
- 封面；
- 详情页；
- 自动回复；
- 预览图；
- 转图片/视频流程；
- 文件命名；
- 交付说明。

但模板化必须建立在首个产品已经完整走通过，而不是一开始就批量铺几十个主题。

#### 6. 内容的目标是触发真实需求，不只是拿互动

研究内容时应区分：

- 点赞；
- 收藏；
- 评论；
- 咨询；
- 商品页访问；
- 订单；
- 退款；
- 复购。

点赞或评论可以作为兴趣信号，但不能直接等同销量。

更有价值的是观察：

- 用户是否主动追问“有没有完整版 / 怎么拿 / 能不能编辑”；
- 同一个主题是否多次带来咨询；
- 内容变化后咨询率是否变化；
- 哪个渠道带来的用户更接近实际买家。

#### 7. 详情页必须消除交付歧义

至少写清：

1. 用户买到什么；
2. 怎么收到；
3. 怎样使用；
4. 适合谁；
5. 不适合谁；
6. 免责声明；
7. 退款规则；
8. 售后方式；
9. 是否更新；
10. 权利与使用限制。

不要用“很全”“超值”“永久更新”替代具体承诺。

#### 8. 产品展示应让用户能判断是否适用

可以使用：

- 实际页面截图；
- 重点页面拼图；
- 目录；
- 真实打开/打印场景；
- 长图预览；
- 翻页或滚动视频；
- 可编辑/可打印说明。

展示的目标不是把装饰做得复杂，而是让用户快速回答：

> 这是不是我现在要用的东西？

模板跑出有效形式后再批量复用。

#### 9. 成交前先确认“用户问的是哪一个产品”

咨询开始时最重要的是定位产品，而不是立刻连发一串广告。

一个稳妥流程：

~~~text
确认用户从哪里来
→ 识别具体资料 / 产品
→ 发目录或预览
→ 明确单份与组合包差异
→ 报价
→ 核实付款
→ 发送对应文件
→ 确认能打开
→ 记录售后问题
~~~

如果用户只需要一份，不必强推大包；如果内容不适用，也不应为了成交隐瞒不匹配。

#### 10. 业务工作台应把“资料—内容—咨询—订单—问题”连起来

资料一多，真正容易出错的是：

- 文件找不到；
- 用户问的是哪一份不清楚；
- 已付款未发货；
- 发错文件；
- 更新后旧预览没有同步。

可以建立六类记录：

| 模块 | 关键字段 |
| --- | --- |
| 资料目录 | 编号、名称、场景、格式、来源、授权、文件位置、价格、更新时间 |
| 对标与选题 | 平台、关键词、样本、评论需求、对应资料 |
| 发布记录 | 账号、内容、时间、链接、对应资料 |
| 咨询记录 | 来源、问什么、预览、报价、当前状态 |
| 订单与发货 | 订单号、产品、实收、收款核实、发货状态、文件位置 |
| 问题记录 | 打不开、发错、缺文件、退款等问题与处理结果 |

用唯一“资料编号 / 产品编号”贯穿整个链路。

自动化可以辅助提醒，但“已付款”不应仅凭客户填写自动认定，仍应由真实支付记录核实。

#### 11. 单位经济必须把时间和售后算进去

至少记录：

~~~text
曝光量
点击量
商品页访问
支付订单
退款
到手收入
工具花费
制作耗时
售后耗时
~~~

可以进一步看两个比值：

- 每千次曝光产生多少收入；
- 每单占用多少分钟。

低客单价不等于低运营成本。链接打不开、自动回复失败、文件兼容、退款和咨询都可能消耗人工。

#### 12. 平台“养号”和引流参数的处理原则

原 K12 教程包含大量具体参数，例如：

- 新号第几天做什么；
- 一天浏览多少小时；
- 加多少人；
- 多久间隔；
- 发几条；
- 私信频率；
- 某些站外联系方式的展示方法。

这些数字主要来自作者经验，并非平台公开的通用安全阈值，且容易随版本、账号状态和政策变化。

因此 NoIT **不把这些参数固化成长期规则，也不收录规避平台限制的技巧**。

只保留上位原则：

- 使用真实身份和真实业务信息；
- 不伪造生活、客户、成交或评价；
- 不用自动化或多账号行为规避风控；
- 遵守当前平台的营销、站外引流、虚拟商品和广告规则；
- 出现限制先看平台提示和官方申诉入口；
- 平台规则在执行前重新核验；
- 内容、账号和渠道变化时一次只改少量变量，才能判断原因。
