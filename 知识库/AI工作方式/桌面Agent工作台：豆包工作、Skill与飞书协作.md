# 桌面Agent工作台：豆包工作、Skill与飞书协作

## 一、工作型 Agent 与普通聊天的关键差异

桌面工作 Agent 不只返回文字，还可能在用户授权范围内读取本地文件、调用浏览器、连接飞书文档、生成演示文稿、改动文件和设置定时任务。因此真正的工作单位是：**输入资料→执行计划→权限确认→生成独立产物→用户检查→版本/回滚**。不要将任务界面上“已完成”误认为文件已经保存、云端数据已正确创建或结果无事实错误。

本篇按 [@yyyole《豆包工作0-1保姆级教程》](https://x.com/yyyole/article/2105673800860004788) 对应的 [万字可读正文](https://www.bukeba.com/article/3cb27ee5bb918006be79c2ff309b6f90) 重建六组完整知识：安装与登录、九类工作入口、PPT/Excel/定时实践、飞书生态、图文视频生态、与 WorkBuddy/Codex 的分工以及五阶段进阶。**2026 年界面、套餐、模型和权限因版本及账号而异；本文不是现有产品的固定 UI 规格。**

## 二、第一次上手：先做一次无风险的文件任务

1. 只从可核验的产品官方渠道取得安装包并确认开发主体，不从陌生网盘安装伪造客户端。
2. 使用当前支持的账号渠道登录，公司的飞书资料应使用有权限的组织账号，并确认组织数据处理规则。
3. 准备两个独立文件夹：`input/` 里放**脱敏副本**，`output/` 放本次生成文件；不开放整个桌面或公司云盘。
4. 尽量采用“始终询问/按需确认”类的受控执行模式；不能把“按需确认”理解为一定拦住所有误操作。
5. 发送第一条受限任务：读取 `input/` 的纪要、提取结论/负责人/日期，在 `output/` 新建 Markdown 或 Word，不修改原件、不得联网或分享。
6. 查看执行计划和最终文件、核对行数/重要事实/来源，记录真实失败点，再决定是否扩展权限。

**三层权限不要混淆**：任务执行时的人机确认模式；连接器所持有的外部账号范围；操作系统给客户端的本机文件/屏幕/麦克风许可。三者缺一不可；“全部允许”不是替用户登录陌生邮箱的万能钥匙。文件有读权限也不代表可擅自发到云端。

## 三、九个工作入口分别承担什么

| 入口类型 | 主要职责 | 验收/风险 |
|---|---|---|
| 新工作任务 | 一次性资料处理、查询、表格、PPT、图片 | 先给输入、输出与禁止动作；打开真实成果 |
| 模型与推理强度 | 任务时选择速度、成本与推理深度 | Auto 不是固定模型，“高”不等于正确 |
| 权限/确认模式 | 控制执行前何时询问用户 | 操作系统及连接器权限另算，敏感任务人工复核 |
| 定时任务 | 按期重复查询/整理任务 | 先手动运行，再定时；可能重复同一错误 |
| Skill 市场/本机技能 | 给具体任务增加处理方法和操作步骤 | 添加技能不等于执行或安全；文件需核验 |
| 连接器 | 邮箱、飞书、网盘、外部工具的访问入口 | 先只读授权，不因连接成功默认可修改数据 |
| 工作伙伴 | 保存经常复用的专业角色与任务偏好 | 角色不等于独立权限或独立模型 |
| 云盘/飞书工作区 | 读取与写回有权限的云文档、表格、Base | 先验证账号、文档位置和共享范围 |
| 项目/最近任务/手机接力 | 保存长期工作边界、继续历史会话或远程接力 | 项目文件夹权限和设备在线状态要单独确认 |

作者客户端界面把入口分布在不同边栏和菜单，具体名称和“九项”归纳随版本会变化。本节强调**功能职责**，不要求用户照图片逐个点完全相同按钮。

### Skill、连接器、伙伴和项目不是同一物

- **Skill**：可复用的工作指令、脚本、参考资料；必须看来源、运行权限和依赖。作者客户端自动发现了本机 Codex Skills，这是单一实测环境，不能推断任意版本均自动识别全部技能。
- **连接器**：经用户授权连接外部资料或工具。能“查”不表示有权“发/改/删”；尤其不要在首次任务就开放删除、分享或发布。
- **伙伴**：预设专业角色和稳定分工，可调用 Skill 和连接器，但不自动拥有所有账号。
- **项目**：为持续数周的事情保存材料与目标，存储位置与已有数据应保持最小权限；不要对一次性任务强制建项目。

## 四、三条入门练习：一次只验证一个能力

### A. PPT：先审页纲，再交文件

原文建议先给已有材料生成 8 页页纲，用户确认后再生成可编辑演示。升级成可验收合同：

~~~text
材料：input/项目研究（已脱敏副本）。
第1轮只交 8 页页纲，标出每页唯一结论及依据。
我确认后，第2轮生成 output/项目汇报_v1.pptx。
不要编造未出现的数字；每个数据标明源页/表。
不要覆盖其他文件，不发送/分享。
验收：8页、文件可编辑、数字可回溯，逐页预览无溢出。
~~~

出错时先定位是材料误读、内容结构还是文件渲染；不能只重试让 Agent “弄得高级一些”。

### B. Excel：结构化清理后再分析

对一份可控 CSV，明确列名、日期和金额单位、缺失值处理、公式是否需要保留，先检查行数及合计，再输出新版本。对于销售表至少核对行数、产品分组、总收入和缺失值，不允许智能体靠猜测给缺失数据填 0。

### C. 定时任务：把正确的手动流程变成计划

先手动检索明确的 3 个信息源过去 24 小时的更新，要求标题、日期、简述、原始链接和“无更新”判定；抽查链接与发布时间。成功后按用户所选时间建立计划，限制为**只查询、只摘要、不发送、不改资料**。保留查看历史执行结果、暂停和故障诊断入口；不要因定时任务存在就声称每次准确。

## 五、飞书生态：云端读写必须做回读验收

有权限的飞书文档、表格或多维表格可以作为任务输入和协作成果的保存位置，但这不意味着 Agent 天然拥有整个公司知识库的访问权。原文用九行销售 CSV 生成 Base 并创建“季度 Q1”字段与按“产品”分组视图，适合说明**写回→重新读取→核对**这一闭环。

最小回读验收：①真的创建了正确名称的新 Base；②记录数仍为九且收入列逐项不丢；③季度字段存在且九条均为 Q1；④分组视图按产品实际可展开；⑤共享权限保持“仅自己可见”，未触碰其他云文档。以上只是原作者展示的示例结果，**本轮没有使用用户飞书创建真实多维表格**。

对飞书/QQ 邮箱等连接器建议先做一条“只读”任务，确认读的是正确账号、文档和日期；如果授权失败，先查连接状态和服务权限，不要先升级到无限访问。

## 六、图像视频生态：区分文件扩展名与真实编码

原文演示按 16:9 需求生成海报，发现导出文件虽以 `.png` 结尾却实际是 JPEG，然后进行格式修复。这是有价值的操作反例：

- 验证图像**真实文件类型**、像素宽高、文字完整度、边缘/中文排版、公开使用许可；
- 不因任务叫“生成 PNG”就省略打开文件/查看元数据；
- 发布前再检查使用的字体/商标、人物肖像、训练素材及是否触发 AI 内容标识要求；
- 从 Word/PPT 继续衍生短视频是可能的下一步，不等于作者已实际测试所有视频模型与权限。原文仅完成图片生成，并未实测 Seedance 的视频生产效果。

## 七、与 WorkBuddy、Codex 的选择关系

- 资料主要在**飞书**：优先评估是否已有可授权读写的飞书入口，可减少导出/回传的工作；
- 资料主要在腾讯生态：可比较 WorkBuddy 对 QQ 邮箱、腾讯文档、会议和企业微信的具体权限与输出能力；
- 主要工作是**改真实代码、跑测试、做 Git PR**：优先选可访问真实工程与测试环境的编码 Agent；
- 主要是单次文件整理：不必先安装多模型、多伙伴、复杂连接器或后台常驻 Agent。

以上是工作路由而非市场排名。不能只依据作者界面上展示“211 个技能”“129 个连接器”“某模型限免”或产品宣传判断当前账号的可用性。选择标准仍是**数据所在、授权范围、可执行动作、交付格式、可验证结果、实际价格**。

## 八、五级升级路线与失败回退

1. 脱敏段落 → 只整理，不触外部文件；
2. 受控副本 → 新文件输出，不覆盖；
3. PPT/Excel → 文件逐页或逐行验收；
4. 飞书等连接器 → 先只读，随后授权创建测试文档，执行结果回读；
5. 项目、伙伴、定时、远程接力 → 仅在前面流程稳定且明确权限/通知后配置。

每级要留下成功/失败的可复查证据，报错时先检查权限、真实目录、任务执行日志、连接器状态、模型额度和导出格式；不要为解决一个小报错授予客户端全部磁盘和通讯录权限。涉及发送、删除、公开分享、购买和后台定时动作须单独授权。
