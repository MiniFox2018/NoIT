# AI基础概念：模型、上下文、记忆与Agent体系

> 给第一次系统接触 AI 的读者一张概念关系图。这里的解释关注长期有效的原理；不同产品、版本和订阅方案如何实现这些能力，必须另查当前官方说明。

## 一、先看全局：模型不是应用，回答也不等于执行

一次常见的 AI 任务可以被理解为：

```text
人提出目标（Prompt）
  + 当前可用信息（Context）
      ↓
模型理解与生成（LLM / 多模态模型；按 Token 处理部分信息）
      ↓
回答 / 生成内容
或者：Agent 选择已授权的工具 → 读取执行结果 → 再决定下一步
      ↓
经验证的交付
```

支持长期保存的知识库、跨对话记忆、可复用 Skill 与固定工作流，分别为这个过程提供材料、延续性、方法和执行组织；**它们不是同一个东西，也不会因为被命名就自动生效**。

## 二、11 个基础概念

### 1. 大语言模型（LLM）

LLM（Large Language Model）是通过训练获得文本理解与生成能力的模型。它能够处理提问、解释概念、起草、归纳和编程辅助等任务，但输出仍有错误可能。

需要分开看三个层次：

- **模型**：负责推断和生成；
- **应用**：把模型包装为聊天界面、文件处理或其他用户功能；
- **工具与外部系统**：真正访问网页、读取仓库、编辑文件或调用服务。

例如聊天应用能上传文件，不意味着底层模型天然就持有所有上传文件；要确认本轮究竟读取了哪些内容。

### 2. 多模态（Multimodal）

“模态”指文字、图像、声音、视频等信息形式。多模态系统可以跨一种或多种形式理解输入，也可能生成不同形式的输出。

至少检查两个维度：**能输入什么**与**能输出什么**。能理解图片不等于会生成视频；能转录语音不等于具有实时双向语音能力。能力还取决于应用是否开放相应接口。

### 3. 提示词（Prompt）

Prompt 是交给模型的当前任务说明，不限于短句。最简洁的有效表述通常包括：做什么、依据什么、有什么约束、结果怎么验收。

例如“把会议记录整理成决定、负责人、截止时间；原文没有的值写未确定”，比“帮我总结一下”具有可核验的输出边界。Prompt 不能替代实际来源、权限或工具。

### 4. 词元（Token）

Token 是模型处理文本时使用的计量单元，不等于一个汉字、一个英文单词或一个字符。不同分词器对同一句话的拆分可能不同。

它常出现在两种指标中：

- **成本**：某些 API 按输入 Token、输出 Token 等统计，具体规则因服务而异；
- **容量**：上下文窗口通常以 Token 表示，表示一轮模型可以处理的信息上限，而不是历史对话总储存量。

文本、图片与音频的计量方式不能简单按“字数”换算。

### 5. 上下文（Context）

上下文是模型**在本次响应中实际获得并可利用**的信息：当前指令、若干历史对话、检索出的材料、文件片段、工具返回等。模型无法仅凭一段对话推知从未交给它的私人数据。

上下文窗口有容量约束。长对话可能经历裁剪、压缩或选择性检索，不能把“过去说过”直接等同于“本轮还看得到”。关键任务应显式携带最新版本、已确认决策与必要证据。

### 6. 记忆（Memory）

记忆是某些 AI 产品跨会话保留并再次调用用户偏好、项目背景等信息的机制。它取决于具体应用的设置、保存策略、召回与权限，不是所有模型共有的固定能力。

**区别**：上下文回答“这一次能看到什么”，记忆回答“以后可能再次取出什么”。若项目交接很重要，可另写一份结构化交接文档：当前目标、已确认决定、最新文件、未完成事项和风险。不能把记忆当作不可变的项目数据库。

### 7. 知识库（Knowledge Base）

知识库负责组织可长期查找的材料：规则、文档、教程、案例、原始证据和版本记录。文件已经放入库中，不表示每次向 AI 提问时都会被自动读取。

知识库与检索增强生成（RAG）的关系是：先按查询检索相关文档或片段，再将检索结果纳入当次上下文，最后生成答案。检索到片段也可能遗漏上下文，所以高准确度任务仍需校核原始证据。

NoIT 的正式知识优先保留可独立学习的正文，而不是只留下跳回原网页的链接。

### 8. 智能体（Agent）

Agent 是围绕目标不断决策并执行的一类系统，典型循环是：

```text
明确目标 → 分解任务 → 选择工具 → 执行 → 观察反馈
       ↑                         ↓
       └──────── 调整下一步 ──────┘
```

与只生成文字的模型不同，Agent 的实际能力受**可用工具、访问权限、外部环境、成本和失败恢复机制**限制。“能计划”不等于“已执行”；“执行一次”不等于“成功验收”。

### 9. 技能（Skill）

Skill 是供 Agent 重复使用的方法包，可包含操作说明、示例、模板、参考资料、脚本与资产。它解决的是“同类任务按什么过程做”，而非天然提供登录账号、网页权限或外部 API。

适合 Skill 的任务：稳定重复的代码审查、文档生产、特定素材的规范化处理。一次性轻量问答只用 Prompt 通常更直接。真正需要外部实时能力时，再接工具或相应协议。

### 10. 工作流（Workflow）

工作流把任务的节点、顺序、条件和输出接口安排好，可以是固定流程，也可以在局部使用 Agent。

| 方式 | 关键特点 | 适合 |
| --- | --- | --- |
| 固定工作流 | 步骤相对可预测、容易重复测试 | 数据清洗、审批、固定报表 |
| Agent 主导 | 按中间结果动态决定下一步 | 开放式研究、跨文件调试 |
| 混合流程 | 固定关键门槛，局部由 Agent 灵活处理 | 大多数需要审计的生产任务 |

Skill 可以承载一种工作流，但不能把所有工作流直接称为 Skill。

### 11. AI 幻觉（Hallucination）

幻觉指模型生成了没有相应事实依据或与证据不匹配的内容。典型例子是虚构论文、捏造引用、把来源未说过的话当成来源结论。

至少区分两种故障：

- 缺少背景：回答笼统，但未必捏造事实；
- 内容无依据：具体断言、数据或引用与真实材料不符。

联网与工具可以补充证据，但**搜索过不等于核验过，引用了链接不等于链接支持该断言**。重要任务应回到原文逐项验证，记录无法确认的部分。

## 三、一次实际任务怎样选用这些能力

假设要分析某类海外用户的产品抱怨：

1. 用 Prompt 说明目标人群、待验证假设、允许使用的来源与结果格式；
2. Agent 在获得工具权限后查找帖子并读取内容；
3. 将帖子链接、摘录和日期作为当次 Context，不将 AI 臆测当作用户原话；
4. 将去重、标签、证据分级组织成 Workflow；
5. 重复任务成熟以后，再沉淀成 Skill；
6. 把可复用的方法与来源写入 Knowledge Base，保留后续核验入口；
7. 用实际付费、候补名单、访谈等行为证据验证需求，而不是把评论热度当成商业成功。

## 四、判断一款 AI 产品宣传是否可信

- “模型更强”：看公开任务、测试条件与自己的真实案例；
- “超长上下文”：问清限制与实际检索/裁剪策略；
- “长期记忆”：问清保存、读取、纠错和访问范围；
- “内置 Agent”：核实真实可调用的工具、权限与失败反馈；
- “一键 Skill”：阅读实际执行说明、依赖和安全边界；
- “自动完成”：要求提供产物、执行记录和可复现验收。

这些概念构成学习地图，而不是功能购买建议；产品能力会随着版本更新。
